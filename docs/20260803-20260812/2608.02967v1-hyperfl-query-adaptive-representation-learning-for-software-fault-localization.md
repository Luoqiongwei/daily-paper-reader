## 摘要
软件缺陷定位识别导致所报告问题的代码位置，是自动化调试和程序修复的基础步骤。近年来，基于检索的方法通过学习问题报告与源代码之间的共享嵌入空间，将缺陷定位表述为稠密检索任务。然而，这些方法对所有问题报告使用固定的查询表示进行编码，而现实世界中的问题报告在长度、结构和调试信息等方面差异显著。为解决这一局限，我们提出HyperFL，一种用于软件缺陷定位的查询自适应表示学习框架。HyperFL采用轻量级超网络为查询编码器生成查询特定的LoRA参数，从而实现动态查询自适应，同时保持代码编码器固定且可复用。在真实世界问题定位基准上的实验表明，HyperFL在多个嵌入骨干上一致地提升了检索性能，在函数级MRR@10上相对提升了高达13.3%，在Hit@1上相对提升了16.7%，优于现有最优方法SweRank。进一步分析表明，HyperFL针对不同问题特征学习了不同的自适应模式，凸显了查询自适应表示在软件问题定位中的有效性。

## Abstract
Software fault localization identifies the code locations responsible for reported issues and is a fundamental step toward automated debugging and program repair. Recent retrieval-based approaches formulate fault localization as a dense retrieval task by learning a shared embedding space between issue reports and source code. However, these methods encode all issue reports using a fixed query representation, despite the substantial diversity of real-world issue reports in length, structure, and debugging information. To address this limitation, we propose HyperFL, a query-adaptive representation learning framework for software fault localization. HyperFL employs a lightweight hypernetwork to generate query-specific LoRA parameters for the query encoder, enabling dynamic query adaptation while keeping the code encoder fixed and reusable. Experiments on a real-world issue localization benchmark demonstrate that HyperFL consistently improves retrieval performance across multiple embedding backbones, achieving up to 13.3% relative improvement in function-level MRR@10 and 16.7% relative improvement in Hit@1 over the state-of-the-art method SweRank. Further analysis shows that HyperFL learns distinct adaptation patterns for different issue characteristics, highlighting the effectiveness of query-adaptive representations for software issue localization.

## 1. 核心问题与整体含义

- **研究背景**：软件缺陷定位（Fault Localization）旨在找出导致已报告问题的代码位置，是自动化调试与程序修复的基础。基于检索的方法将缺陷定位建模为“问题报告—源代码”的稠密检索任务，使用共享嵌入空间计算相似度。
- **核心问题**：现有检索模型对所有问题报告使用**固定查询表示**，但真实世界的问题报告在长度、结构、调试信息（如堆栈追踪、错误消息、代码片段）等方面差异巨大。单一共享查询表示无法捕捉不同报告中最具信息量的语义模式，限制了定位精度。
- **整体含义**：论文提出应针对每个查询动态调整其表示，同时保持代码表示的固定与可复用，以在效率和效果之间取得更好平衡。

## 2. 方法论

- **核心思想**：HyperFL 采用一个**轻量级超网络**为查询编码器生成**查询特异的 LoRA 参数**，实现查询级动态自适应。代码编码器完全冻结，代码嵌入可预计算并复用，保留稠密检索的高效性。
- **技术流程**：
  1. **初始查询编码**：使用冻结的查询编码器（带检索指令前缀）对问题报告编码，得到初始查询表示，并做 L2 归一化。
  2. **全局上下文融合**：维护 K 个可学习全局嵌入，经 GRU 汇总为全局上下文向量；将初始查询表示与全局上下文拼接，经线性投影得到条件向量。
  3. **层特定条件生成**：对每个目标变换层，使用独立 GRU 将条件向量转换为层特定条件向量。
  4. **查询特定 LoRA 生成**：将层特定条件向量与共享局部嵌入拼接，经投影网络（LayerNorm + GeLU + Dropout + Linear）生成查询特定的 LoRA 矩阵 A；互补矩阵 B 可训练但跨查询共享。
  5. **动态权重更新**：预训练权重固定，查询编码时叠加 ΔW = α/r · BA 的低秩更新。
  6. **非对称编码**：查询编码器应用生成的 LoRA 参数再次编码；代码编码器保持冻结，代码向量可缓存复用，最终以余弦相似度排序。
- **训练**：使用 InfoNCE 损失，温度 τ=0.05，每个查询 10 个负样本。负采样策略为先用 BM25 排序，丢弃最难候选，从剩余池中随机抽样中等难度负样本，以减少误标/近正样本的影响。训练期间仅优化超网络、全局上下文、局部嵌入等新增组件，预训练编码器完全冻结。

## 6. 主要结论与发现

- HyperFL 在多个嵌入骨干上**一致提升**定位性能；在 CodeRankEmbed 骨干上与 SweRankEmbed-Small 相比，函数级 MRR@10 相对提升 13.3%（0.45→0.51），Hit@1 相对提升 16.7%（0.36→0.42）。
- 最佳配置（Jina-Code-v2 骨干）达到函数级 MRR 0.57、Hit@1 0.47。
- **问题特性差异显著影响增益**：对性能相关、含丰富调试上下文的问题收益最大；对原本易被固定表示处理的问题则保持竞争力，说明自适应能力集中在最需要的地方。
- 超网络生成的 LoRA 参数在不同问题聚类间呈现**不同的层间适应模式**，证明模型学习了查询相关的结构化自适应，而非统一更新。
- **训练数据质量至关重要**：BM25 过滤阈值 K=30 最优；完全不过滤时噪声数据导致 MRR 从 51.3% 降至 42.5%，说明自动构建高质量训练对对于检索式定位至关重要。

## 7. 优点

- **方法创新性**：首次将查询级自适应表示学习引入检索式缺陷定位，通过超网络生成查询特定 LoRA，突破了固定查询表示的局限。
- **高效性与可复用性**：代码编码器冻结、代码嵌入缓存，额外计算开销小，适合大规模仓库检索。
- **通用性**：在多个不同规模/类型的预训练嵌入模型上均验证了优势，不依赖特定骨干。
- **分析深入**：通过聚类分析、层间适应可视化等手段，揭示了自适应表示的工作机理，增强了方法可信度。
- **数据构建策略合理**：采用 BM25 过滤构建中等难度负样本，并分析了过滤阈值影响，提供了可操作的实践指导。

## 8. 不足与局限

- **实验规模有限**：自建基准仅有 5 个仓库、369 个 issue，统计显著性有待更大规模验证；仓库多样性也局限于 GitHub 上的少数项目。
- **对比范围不完整**：未与 AutoFL、AgentFL 等基于 LLM 的多轮推理定位方法比较；虽然这些方法成本更高，但合理的比较有助于全面定位 HyperFL 的实际价值。
- **训练数据潜在偏差**：使用 BM25 过滤训练对可能引入与检索难度相关的偏差，且 ground-truth 仅来自修复提交中修改的函数，可能遗漏未修改但相关的位置。
- **泛化性收益有限**：在 SWE-bench Lite 上增益较小，说明在已有较易表示的问题上优势不明显；方法可能更适用于复杂、异构的问题报告。
- **资源披露不足**：未报告训练时间、模型参数量增量等具体计算成本，影响可复现性和实践评估。
- **超参数敏感性未充分探索**：LoRA 秩、缩放因子、目标层选择、全局上下文数量 K 等对性能的影响未做系统分析。
