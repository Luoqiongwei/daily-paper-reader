## 摘要
大型语言模型（LLMs）在回归预言补全（给定测试前缀，并将当前程序版本视为预期行为）方面展现出强大潜力。近期方法越来越依赖迭代式自我修复和执行反馈，但优化执行成功率并不一定能产生强大的故障揭示预言。这一目标在基于修复的方法中被广泛采用，仅作为代理指标，可能与预言生成的真正目标不一致。这种不一致使修复过程产生偏差，导致一种由反馈驱动的退化，我们称之为“自我修复陷阱”：迭代式修复逐渐驱使模型生成更易满足但检测故障效果较差的断言。为解决这一问题，我们提出DCAware，一种计算高效的非迭代框架，其优先考虑高信噪比的上下文基础，而非多轮修复。DCAware将结构化静态上下文与选择性检索的动态状态相结合，无需迭代反馈循环即可实现精确而稳健的预言生成。基于执行测试和变异测试的大量实验表明，DCAware在保持高执行成功率的同时，持续提升故障揭示有效性，并以显著更低的计算成本超越先前方法。我们的结果表明，在所研究的回归预言场景中，提升上下文质量比增加迭代修复复杂性更为有效。

## Abstract
Large Language Models (LLMs) have shown strong potential for regression-oracle completion, where a test prefix is given and the current program version is treated as expected behavior. Recent approaches increasingly rely on iterative self-repair and execution feedback, but optimizing execution success does not necessarily yield strong fault-revealing oracles. This objective, widely adopted in repair-based methods, serves only as a proxy and may be misaligned with the true goal of oracle generation. Such misalignment biases the repair process, giving rise to a feedback-driven degeneration that we term the Self-Repair Trap, where iterative repair progressively drives models toward assertions that are easier to satisfy but less effective at detecting faults. To address this issue, we propose DCAware, a computationally efficient, non-iterative framework that prioritizes high signal-to-noise contextual grounding over multi-round repair. DCAware integrates structured static context with selectively retrieved dynamic states, enabling precise and robust oracle generation without iterative feedback loops. Extensive experiments based on execution and mutation testing show that DCAware consistently improves fault-revealing effectiveness while maintaining high execution success, outperforming prior methods with substantially lower computational cost. Our results suggest that improving contextual quality is more effective than adding iterative repair complexity in the studied regression-oracle setting.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：单元测试是软件可靠性的重要保障，其中测试预言（test oracle）用于判断程序行为是否正确。在“回归预言补全”任务中，给定可执行的测试前缀，并将当前程序版本视为预期行为，自动补全缺失的断言（assertion）。
- **核心问题**：现有基于 LLM 的方法（如 ChatAssert）依赖“生成-执行-修复”迭代循环，并以“执行成功率”作为优化目标。但执行成功只是一个代理指标，与真正目标（生成能揭示故障的强断言）存在错位。这种错位会使模型在修复失败断言时倾向于生成更容易满足、但故障检测能力更弱的断言，作者称之为 **“自我修复陷阱”（Self-Repair Trap）**。
- **整体含义**：论文提出，高质量预言生成不需要多轮试错修复，而应依赖高信噪比的上下文基础。提升上下文质量比增加迭代修复复杂度更有效、更经济。

## 2. 方法论

- **核心思想**：提出 **DCAware**，一种非迭代、计算高效的双上下文感知框架。它通过“静态上下文感知 + 动态上下文感知”为 LLM 提供精确的上下文锚点，一次性生成断言，无需执行反馈循环。
- **三阶段流程**：
  1. **静态上下文感知（Static Context-Aware）**：
     - 使用 JavaParser 提取三类静态结构，并执行 **Contextual Semantic Folding**（上下文语义折叠）：保留类/方法签名、导入、被调用方法体，折叠无关方法体，压缩信息噪声。
     - 具体包括：`Callees`（测试前缀中调用的方法）、`Focal Class`（目标焦点类及其兄弟方法签名）、`Test Class`（测试类骨架、生命周期方法）。
     - 目标：在不丢失依赖关系的前提下，提高 LLM 对代码结构理解的准确率。
  2. **动态上下文感知（Dynamic Context-Aware）**：
     - 采用 **Intent-Driven Dynamic State Extraction**（意图驱动的动态状态提取）。
     - 将 LLM 视为“主动调试器”：先基于静态上下文生成需要的运行时查询列表（变量、表达式、无副作用函数调用）。
     - 自动注入断点、启动 Maven 调试进程，通过 JDB（Java Debugger）评估查询并返回值；失败查询记录错误信息，不影响其他查询。
     - 只返回语义相关的动态状态，避免“全量转储局部变量”带来的噪声。
  3. **Oracle 生成（Oracle Generation）**：
     - 将折叠后的静态上下文与意图驱动的动态上下文一起输入 LLM。
     - 通过 **Anti-Overfitting Guardrails**（防过拟合护栏）避免生成依赖内存地址、时间戳等不稳定信息的脆弱断言，鼓励使用 `.size()` 或确定性业务字段进行断言。
     - 模型一次生成最终断言，完全绕过二次执行和修复循环。

## 3. 实验设计

- **数据集**：使用 TECO 数据集中与 ChatAssert 官方评估完全一致的 500 个断言补全实例，来自 38 个开源 Java 项目；每个问题对应一个测试方法中的单断言补全。最终过滤得到 362 个变异测试有效问题。
- **基线方法**（7 类）：
  - 训练类：TECO（CodeT5）、TOGA（CodeBERT）、LLM-AG（CodeT5）、TOGLL（CodeGen、CodeParrot 两种变体）。
  - LLM 类：ChatAssert（迭代修复方法）、Direct Prompting（单次直接提示）。
  - 规则类：Trivial（仅生成 `assertTrue(true)`，作为下限）。
- **模型**：主实验使用 Qwen3-Coder-30B-A3B-Instruct-FP8（本地部署）和 GPT-5-mini（Azure API）；额外验证使用 GPT-5。
- **评估指标**（动态执行式）：

## 6. 主要结论与发现

- **DCAware 显著优于所有基线**：
  - Qwen3-Coder-30B：Pass Rate 80.8%（ChatAssert 68.4%），KG 73.2%（ChatAssert 59.0%）。
  - GPT-5-mini：Pass Rate 88.2%（ChatAssert 73.2%），KG 78.2%（ChatAssert 61.6%）。
- **验证了“自我修复陷阱”**：ChatAssert 越晚修复（多轮）通过的新断言往往越弱，累积通过率上升但故障检测能力下降。
- **静态上下文**：完整静态上下文能最大化执行通过率，但在 Shared KG 上略低于某些删减配置，说明上下文扩大带来注意力噪声与断言强度的权衡。
- **动态上下文**：全量转储局部变量（Locals）无法稳定提升性能，甚至可能降低 Shared KG；DCAware 的定向检索显著提升通过率和故障检测能力。
- **静态与动态互补**：静态上下文为动态查询提供“锚点”，缺少静态上下文时动态查询“盲目”；两者结合在 Qwen3 上得到最高 Shared KG，在 GPT-5-mini 上大幅提升 Pass Rate。
- **成本优势**：DCAware 生成 token 仅为 ChatAssert 的约 1/12，执行时间最高降低约 77%，API 成本约为后者的 1/4。
- **模型差异**：Qwen3-Coder-30B 更注重断言严格性，GPT-5-mini 更注重可执行性；在共同样本上 Qwen3 的 Shared KG 更高。

## 7. 优点

- **问题发现新颖**：首次明确指出“执行成功”作为代理目标与预言生成真实目标之间的错位，并系统刻画了“自我修复陷阱”。
- **方法设计高效**：用非迭代、单次生成代替多轮修复，大幅降低计算成本，同时提升质量。
- **上下文构建有启发性**：通过语义折叠提升信噪比，并通过意图驱动检索动态状态，避免噪声淹没模型注意力。
- **评估方式严谨**：使用执行式指标 + PITest 变异测试，避免静态指标（EM、ROUGE、CodeBLEU）的误导性；比较时使用共同通过样本的 Shared KG，减少偏差。
- **鲁棒性考虑充分**：防过拟合护栏、缓存隔离、多次运行稳定性验证、不同模型验证，增强了结论可信度。

- **任务范围有限**：仅研究回归预言补全，且只处理单断言；多断言、更复杂的测试场景不在范围内。
