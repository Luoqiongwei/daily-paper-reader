## 摘要
进化式代码搜索中的成功变异策略可能包含可重用的知识，这些知识在单次运行之外仍有用，并且在某些情况下可以跨相关任务和领域迁移。然而，现有的基于LLM的进化框架在很大程度上丢弃了此类知识，反复重新发现类似的想法，限制了跨运行和跨任务学习的机会。我们提出了EvoMem，一种用于基于LLM的进化程序搜索的持久记忆架构，它捕获并重用候选变异知识。EvoMem将成功的变异事件转化为结构化的、具有任务意识的建议，供未来运行使用。它分两个阶段运行：每次运行后，它提取并存储具有来源的可行想法；在后续进化过程中，它根据当前任务和程序上下文检索一小部分相关指令来指导变异。在几何优化、多跳问答、GPU内核优化及相关基准测试中，我们的实验显示，在大多数评估设置下，目标指标或搜索速度均有正向平均改进，同时也揭示了跨任务的变异性。总体而言，EvoMem提供了证据表明，持久记忆可以减少一些冗余探索，并改进在LLM驱动的进化搜索中成功策略的复用与适应。

## Abstract
Successful mutation strategies in evolutionary code search may contain reusable knowledge that is useful beyond a single run, and in some cases may transfer across related tasks and domains. However, existing LLM-driven evolutionary frameworks largely discard such knowledge, repeatedly rediscovering similar ideas and limiting opportunities for cross-run and cross-task learning. We introduce EvoMem, a persistent memory architecture for LLM-based evolutionary program search that captures and reuses candidate mutation knowledge. EvoMem converts successful mutation events into structured, task-aware advice for future runs. It operates in two phases: after each run, it extracts and stores promising ideas with provenance, and during subsequent evolution, it retrieves a small set of relevant instructions based on the current task and program context to guide mutation. Across geometric optimization, multi-hop question answering, GPU kernel optimization, and related benchmarks, our experiments show positive average improvements in target metrics or search speed for most evaluated settings, while also revealing variability across tasks. Overall, EvoMem provides evidence that persistent memory can reduce some redundant exploration and improve the reuse and adaptation of successful strategies in LLM-driven evolutionary search.

- **整体含义**：论文提出一个核心假设——成功变异策略中包含的知识比其出现的单一程序更通用，跨运行、跨任务的持久记忆可以降低搜索成本、加速收敛，并提升最终目标指标。
- **与现有工作对比**：当前进化搜索框架将每次运行视为孤立过程；简单地跨实验混合种群或重用已有代码行不通，因为具体程序常与特定任务、指标和接口绑定。需要一个机制来抽象可复用知识、保留来源可审计性，并在变异时只检索少量相关建议注入提示词。

### 二、论文提出的方法论

#### 核心思想
EvoMem是一种**持久记忆架构**，作为GigaEvo（AlphaEvolve风格的开源实现）的扩展。它将成功变异事件转化为结构化的“记忆卡片”（memory cards），在后续进化运行的变异提示中注入少量相关建议，但不改变底层进化循环。

#### 两阶段架构
- **写阶段（离线，Run结束后）**：
  - 从完成的进化运行中收集程序，过滤根程序、无效输出。
  - 经后运行分析（Post-run Analysis）将候选程序归一化为记录，包含适应度、代数、亲本关系、任务上下文、变异策略、代码和变更描述。
  - 两种分析模式：默认分析器（LLM判断改进是否为新思想、修订或复述）和快速分析器（DBSCAN聚类 + LLM精炼，用于大量相似描述的场景）。
  - 经过“起源分析”（Origin Analysis）识别高价值思想：要求有可识别的引入点、优于最强亲本、很少产生更差后代，并至少有一个额外信号（如近邻重复出现、与同上下文兄弟比较优势、在后代精英谱系中扩散）。
  - 使用保守去重策略：重复观察更新已有记录并扩展来源；具体程序记录无语义合并；抽象思想卡片仅在描述相同底层机制时合并。LLM决策策略决定存储、丢弃或合并，模糊案例保留为新卡片以偏向召回。
  - 可选使用统计追踪：记录每个记忆项的**Δf = f(child) − max_{p∈parents} f(p)**（仅当子代和亲本均通过有效性检查时计算），用中位数聚合应对稀疏且重尾的进化适应度变化。

- **读阶段（在线，每次变异前）**：
  - 根据当前任务描述、指标描述、变异模式、父程序和局部上下文构建查询。
  - **Task-scope过滤**：先由LLM从记忆库中选出潜在相关源任务，后续检索仅在这些任务关联的思想中进行。
  - **多通道检索排序**：基于词法与嵌入相似度，对卡片的机制描述、源任务上下文、解释等多种语义视图进行评分，权重组合为 **score(c) = Σ_{q∈Q} w_q·s_q(c)**，默认权重最大在描述和描述-解释视图。
  - 检索迭代次数与返回卡片数均预先固定（默认k=3卡片，max_iters=3），保证变异时操作有界。
  - 检索到的建议以**建议而非硬约束**的形式插入变异提示中，并记录所选记忆卡片ID以支持后续使用统计。

#### 数据流表示
> Pr --extract--> Cr --write--> M --select(p,τ,μ)--> I_p → mutation prompt

其中Pr为运行r的程序集，Cr为提取的卡片集，M为持久记忆库，I_p为父程序p在任务τ和指标μ下选择的小型指令列表。

#### 设计性质
1. **记忆可选**：对照组和处理组仅差异在于记忆建议通道是否填充，其他组件完全一致。
2. **检索有界**：固定项目和迭代预算。
3. **可审计**：所选记忆卡片与使用它们的候选程序关联，后运行分析可追溯到源程序。

### 七、优点

1. **设计清晰且可控**：两阶段分离（离线写入/在线读取）使昂贵操作与变异时延分离；记忆仅作为建议通道存在，不改变父本选择、验证、评分等核心进化逻辑，因果归因清晰。
2. **可审计性**：完整保留来源信息（源程序ID、代数、亲本关系、使用统计），为跨运行知识追踪提供基础设施。
3. **训练/评测隔离规范**：评估时排除同基准记忆，确保报告的是真正的跨任务迁移而非记忆回溯同任务；消融比较了随机记忆/无任务过滤等条件，证明增益不是来自额外上下文本身。
4. **机制级验证补充**：除端到端指标外，还做了接受率审计和覆盖率分析，让“记忆是否真的被使用”这一问题有直接证据；谱系分析进一步验证了记忆影响经得起进化选择压力的筛选。
5. **提供完整实现与参数**：附录附记忆卡片Schema、读写伪代码、详细超参数，可复现性强。
6. **诚实报告方差**：明确报告各基准最小/最大增益范围、个别加速比低于1（如Circle Packing 26的0.31、KernelBench的0.05等），未选择性隐瞒负面结果。

6. **接受率数字整体偏低**：即使默认检索的接受率也仅4.05%，说明绝大多数检索建议未被实际采纳，记忆对搜索的影响主要发生在少数高质量建议上——效率虽被正名，但机制空间仍有很大改进空间。
7. **无法完全排除混杂因素**：记忆选用的LLM任务范围过滤本身构成额外LLM调用链，这些调用的质量、token消耗与可变性未单独分析；谱系分析是关联性而非因果性证据。
8. **算力成本未透明**：未报告GPU数量、总运行时长、总成本等关键资源指标，难以评估EvoMem在“节省搜索”与“额外记忆开销”（离线分析+在线检索）之间的净收益平衡。
