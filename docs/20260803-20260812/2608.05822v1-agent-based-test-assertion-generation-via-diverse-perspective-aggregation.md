## 摘要
测试断言是单元测试的关键元素，作为验证预期行为并确保软件正确性的检查点。已有众多技术被提出来自动化断言生成，其中近期进展主要由大型语言模型（LLM）驱动。尽管前景广阔，现有方法如ChatAssert仍存在准确性中等、严重依赖过采样以及对模型随机性脆弱（由于单次提示）的问题。为解决这些局限性，我们提出了AssertMate，一种新颖的基于智能体的断言生成框架，通过三个关键组件增强LLM生成断言的质量与可靠性：（1）基于静态分析和类型感知启发式识别断言目标的实际值构造；（2）使用代码生成、检索增强生成（RAG）和思维链（CoT）推理智能体进行多视角期望值预测；（3）采用LLM-as-a-Judge协作机制选择最合适的断言。在Defects4J基准上的评估表明，AssertMate在编译成功率和通过率上显著优于最先进技术，同时具备更高的缺陷检测能力。与EvoSuite的集成进一步验证了AssertMate的实用性，产生了更优的变异覆盖率和杀死数。消融实验显示，三个组件各自对整体性能做出重要且互补的贡献。这项工作证实了聚合多样视角以增强基于LLM的断言生成有效性的巨大潜力。

## Abstract
Test assertions are critical elements of unit tests, serving as checkpoints to validate expected behavior and ensure software correctness. Numerous techniques have been proposed to automate assertion generation, with recent progress notably driven by large language models (LLMs). Despite the promise, existing approaches such as ChatAssert suffer from modest accuracy, heavy reliance on oversampling, and vulnerability to model randomness due to one-shot prompting. To address these limitations, we propose AssertMate, a novel agent-based assertion generation framework that enhances the quality and reliability of LLM-generated assertions through three key components: (1) actual value construction that identifies assertion targets via static analysis and type-aware heuristics; (2) multi-perspective expected value prediction using code generation, retrieval-augmented generation (RAG), and chain-of-thought (CoT) reasoning agents; and (3) an LLM-as-a-Judge collaboration mechanism to select the most appropriate assertion. Evaluation on the Defects4J benchmark demonstrates that AssertMate significantly outperforms state-of-the-art techniques in compilation success and pass rates, along with substantially higher bug detection capabilities. Integration with EvoSuite further validates AssertMate's practicality, yielding superior mutation coverage and kill counts. Ablation studies reveal that each of the three components makes a significant and complementary contribution to the overall performance. This work affirms the great potential of aggregating diverse perspectives to enhance the effectiveness of LLM-based assertion generation.

## 1. 论文的核心问题与整体含义（研究动机与背景）

### 研究背景
- 单元测试是软件质量保障的关键手段，一个完整的单元测试由**测试前缀（test prefix）**和**断言（assertion）**两部分组成。断言作为测试预言（test oracle），决定程序观察行为是否符合预期。
- 尽管 LLM 在可执行测试前缀生成方面已取得显著进展，**断言生成仍是根本性挑战**——即使代码覆盖率很高，若断言弱、不完整或语义错误，缺陷检测能力仍会受限。

### 现有方法的局限性
论文以当前最先进方法 **ChatAssert** 为靶点，指出其三大问题：
1. **准确率中等**：top-1 准确率仅 0.45，top-10 也仅 0.54，即使经过多轮执行-修复后处理。
2. **严重依赖过采样**：需生成多达 10 个断言来覆盖一个可能正确的答案，效率低下且增加人工验证负担。
3. **受模型随机性影响大**：单次提示（one-shot prompting）易产生过度自信或不稳定的输出。

### 核心洞察
- 近期研究（Zhang et al., ACL 2024）表明：**引入多样化的解题视角**能为迭代优化提供更稳健的基础，显著提升输出质量。
- 论文因此提出假设：采用**多视角提示策略**有望增强 LLM 断言生成的有效性和可靠性，但面临三个特有挑战：
  - 单元测试规范不充分，目标行为模糊，LLM 可能在不同视角下产生不一致解释；
  - 多提示策略依赖合理的选择与组合，不当组合可能引入噪声；
  - 多个智能体生成候选断言后，如何选出最准确、语义最对齐的一个成为难题。

### 整体含义
论文提出 **AssertMate** 框架，从"单一整体式断言生成"转向"分解式、软件工程化的工作流"，通过**任务解耦 + 多智能体协同**来提升 LLM 生成断言的质量、可靠性与缺陷检测能力。

## 2. 论文提出的方法论

### 2.1 核心思想：细粒度断言分解
论文将断言形式化分解为三个组件（如图 2 所示）：
- **Assertion Function（断言函数）**：如 `assertEquals`、`assertTrue` 等，定义实际值与期望值之间的关系。
- **Actual Value（实际值）**：被评估的目标元素，由 **Test Target（测试目标，如变量 calc）** 和 **Resolution Path（解析路径，如 `.getScreen().getContent()`）** 组成。
- **Expected Value（期望值）**：实际值的预期结果，可以是具体数据值或选择恰当的断言函数。

### 2.2 框架总览（两阶段流水线 + 三组件）

#### 组件一：Actual Value Constructor（ActVCon，实际值构造器）
解决"**测什么**"的问题，采用静态程序分析与 LLM 辅助的混合规则方法：

1. **测试目标识别**（静态分析）：
   - 焦点方法的**返回值**；
   - 焦点类中**具有公共 getter 的字段**（反映副作用）。

2. **类型感知的迭代遍历**构造实际值，定义三条规则：
   - **原始数据类型**（如 `boolean`、`String`、`Integer`）：直接纳入最终集合，不继续分解；
   - **项目内类型**（In-Project）：附加无参 getter 调用以扩展解析路径，形成新的候选值；
   - **外部类型**（如第三方库）：由于缺乏上下文，借助 LLM 辅助生成最终实际值。

3. **断言函数选择**：聚焦五类常见断言——`assertEquals`、`assertTrue`、`assertFalse`、`assertNull`、`assertNotNull`（占开源仓库断言总量的 86%）。boolean 用 `assertTrue/assertFalse`，其他原始类型用 `assertEquals`，可能为 null 的目标附加空值断言。

#### 组件二：Multi-Perspective Expected Value Generator（EVGen，多视角期望值生成器）
解决"**期望什么**"的问题，设计三个互补的智能体：

| 智能体 | 视角/策略 | 机制 |
|---|---|---|
| **CGA（代码生成智能体）** | 程序语义与代码结构 | 提示模型基于给定实际值补全完整测试断言 |
| **RAGA（RAG 智能体）** | 外部知识与实例参考 | 基于 Jaccard 相似度检索最相似测试用例（借鉴 EditAS），作为 one-shot 示例引导生成 |
| **CoTA（思维链智能体）** | 显式中间推理 | 三阶段推理：焦点方法理解 → 测试场景理解 → 期望值预测 |

关键配套机制：
- **Prompt Prefill（提示预填充）**：在 LLM 响应开头预附加断言函数签名（如 `assertEquals`），约束输出结构，提高可编译性（受 Yang et al., ASE 2024 的预填充模式启发）。
- **概率重排（Probability-Based Re-Rank）**：每个智能体生成 5 个响应（共 15 个候选），仅统计响应中**断言部分 token 的平均概率**作为置信度（排除解释性 token 的干扰），每视角选出最高置信度响应进入协作阶段。

#### 组件三：Collaborative Judge Agent（协作 Judge 智能体）
解决"**选哪个**"的问题，采用 **LLM-as-a-Judge** 范式：
- 当三个视角未达成共识时，由 Judge 智能体进行深入比较分析；
- 使用 CoT 推理评估候选断言的**语义正确性、与测试上下文的连贯性、与实际值的对齐程度**；
- 同样使用 prefill 模式保证结构化、一致的评估输出。

**最终断言** = 断言函数 + 实际值 + 预测期望值，每个断言可独立附加到测试前缀形成完整测试用例。

## 3. 实验设计

### 3.1 数据集与 Benchmark
- **主基准：Defects4J（v2.1.0）**，包含 834 个真实 Java 缺陷，被广泛用于缺陷检测能力评估（其他断言生成数据集不支持该评估）。
- **Human-Written FM-TP 对**（人工编写测试前缀）：筛选触发测试在断言处失败的 bug，结合补丁与测试级证据识别焦点方法，最终获得 **112 个合格 bug → 667 个 FM-TP 对**。
- **EvoSuite 生成的 FM-TP 对**：基于 bug 修复补丁选择焦点方法，用 EvoSuite 默认配置生成测试（每目标 10 分钟），移除所有断言后获得 **2,203 个 FM-TP 对**。

### 3.2 对比方法（四类基线）
| 方法 | 类型 | 核心模型 |
|---|---|---|
| **EditAS** | IR + 深度学习 | 注意力 LSTM 编解码器 |
| **TOGLL** | PLM 微调 | CodeGen-350M（SF110 训练） |
| **RetriGen** | 混合检索 + PLM | CodeT5 |
| **ChatAssert\*** | LLM 提示 | ChatGPT（**禁用修复模块**，因该模块假设"函数无 bug"，与单元测试场景矛盾） |

### 3.3 评估指标
- **CSR（编译成功率）**：语法正确性；**PR（通过率）**：功能正确性（断言-候选级别，归一化预算，避免将断言质量与数量混淆）。
- **BDR（缺陷检测率）**：检测真实 Defects4J bug 的比例。
- **变异测试指标**：#Covered Mutants、#Killed Mutants、Kill Rate。
- **效率指标**：Token Overhead（每查询平均 token 数）、Average Time（每 FM-TP 对平均处理时间）。
- 所有 LLM 方法独立运行 **5 次**，报告均值和样本标准差；用 **Wilcoxon 符号秩检验**（p 值）和 **Cliff's delta（δ）** 评估显著性。

### 3.4 三个研究问题
- **RQ1**：AssertMate 与现有方法的有效性对比（Human-Written 测试前缀）。
- **RQ2**：AssertMate 与 EvoSuite 集成的实用性（变异测试评估）。
- **RQ3**：各组件的消融贡献分析。

## 6. 论文的主要结论与发现（续）

1. **AssertMate 在所有有效性指标上显著优于现有方法（RQ1）**  
   在 Human-Written FM-TP 对的 667 个测试前缀上，AssertMate 的 CSR、PR 与 BDR 均取得最高值。相比最强的基线 ChatAssert\*，AssertMate 在 top-1 断言下的 PR 提升约 15–20 个百分点（论文中以归一化预算计算，避免数量优势干扰），BDR 同样显著领先。统计检验（p<0.05，Cliff's δ 多为“大”效应量）证实了优势的显著性。

2. **多视角聚合优于任何单一视角，协作 Judge 是最后一道质量闸门（RQ3）**  
   消融实验显示：
   - 去除 ActVCon 后，AssertMate 的 PR 与 BDR 均显著下降，说明“测什么”的精确构造是高质量断言的前提；
   - 单独使用 CGA、RAGA、CoTA 时，三者各有优劣但均不如完整版，证明了视角互补的必要性；
   - 使用 Debate 或 Voting 替代 Judge 时，聚合准确率下降，而 Judge 的 CoT 比较分析能更有效识别语义不一致的候选断言，McNemar 检验确认其覆盖率优势显著。

3. **在 EvoSuite 集成场景下仍有效，且能提升变异杀死率（RQ2）**  
   将 AssertMate 用于 2,203 个 EvoSuite 生成的 FM-TP 对时，其生成的断言比 EvoSuite 原始断言和 TOGLL 生成的断言杀死更多变异体。Kill Rate 显著提升，且与原始 EvoSuite 相比边际增益稳定，说明 AssertMate 不仅能处理人工前缀，也能处理自动化生成的前缀，实际可集成进既有测试生成流程。

4. **发现并验证了 TOGLL 的数据泄漏问题，增强对比公平性**  
   论文发现 TOGLL 的训练数据中包含 Defects4J 版本的测试代码，存在训练-测试重叠。为公平对比，作者用剔除重叠数据后的语料重新训练 TOGLL（TOGLL\_DN），其 Kill Rate 从 18.39% 跌至 6.52%，证明原 TOGLL 的优势大量来自记忆而非泛化能力。这一发现为后续基准对比提供了重要警示。

5. **在更强 LLM 下仍有提升空间，但收益递减**  
   使用 QC-32B 和 DR-32B 作为后端模型时，AssertMate 的 PR 与 BDR 均进一步提升，且 RAGA 在更大模型上更受益于检索示例。不过模型中部分视角（如 CoTA）在更强推理模型上的增益不如 Judge 组件显著，说明多视角框架的收益与基座模型能力存在一定交互。

6. **效率代价可控但 token 开销需权衡**  
   AssertMate 平均生成时间为 15.31 秒/前缀，较 ChatAssert\*（13.27 秒）仅稍慢，但 token 开销为后者的 3.28 倍。论文认为这是为了实现更强语义对齐而付出的合理代价，是准确性与计算成本之间的显式折中。

## 7. 论文的局限与可能的不足

- **依赖固定断言函数集合**：ActVCon 只覆盖五类常见断言（86%），但剩余 14% 的断言（如 `assertArrayEquals`、`assertSame`、自定义断言）未被支持，可能限制在特定项目上的表现。
- **LLM 概率重排的置信度信号局限**：以生成 token 的平均概率作为置信度，可能无法完全反映语义正确性；低概率 token 也可能构成正确断言，高概率 token 组合也可能语义错误。
- **基准规模有限**：主实验的 667 个 FM-TP 对来自 112 个 Defects4J bug，尽管真实，但数量仍偏小；结果可能在更广泛的项目与语言（非 Java）上不成立。
- **仅支持 Java**：静态分析规则、树解析、EvoSuite 集成均为 Java 生态定制，限制了框架向其他语言的迁移。
- **Judge 评估的主观性风险**：LLM-as-a-Judge 模式缺乏理论保证，可能偏好某些表述风格或模型自身生成模式；paper 未给出 Judge 与人类标注的一致性独立评估。
- **修复模块的排除可能低估 ChatAssert**：ChatAssert 原版的执行修复模块在假定“函数无 bug”的场景下工作，但论文简单禁用该模块，可能导致基线不如原版表现，虽公平但未必能完全代表其实际能力边界。
- **未分析失败案例模式**：论文未系统性总结 AssertMate 在哪类断言上仍失败（如复杂对象状态、浮点比较、并发相关断言），不利于后续针对性改进。

## 8. 对未来工作的启示

- **扩展断言类型与上下文感知**：将五类断言扩展到更丰富的断言模式（如数组、近似值、集合比较），并进一步利用类型信息推断比较语义。
- **更可靠的概率校准**：探索基于训练/校准的置信度估计（如 ChatBot Arena 式对 U 评测、语义相似度加权）以替代简单 token 平均概率。
- **跨语言适配**：将静态分析规则泛化到 Python、Go、Rust 等项目，验证多视角框架的通用性。
- **自适应视角选择**：根据输入用例特征动态选择视角组合（如在简单 setter 场景下跳过 CoTA），以降低 token 开销。
- **与测试生成流水线深度融合**：将 AssertMate 与搜索空间探索结合，将每轮生成的断言质量反馈给前缀生成器，形成闭环优化。
- **揭示数据泄漏的通用方法**：建立更严格的数据集污染检测标准（如 n-gram 重叠、test-oracle 泄漏），提高大模型时代测试生成基准的可信度。

## 9. 综合评价

**贡献亮点**：
- 从软件工程视角重新定义了 LLM 断言生成任务：将其分解为“测什么—期望什么—选什么”三个可独立优化的子问题，架构清晰、思路新颖。
- 创新组合静态分析 + 多智能体异构视角（语义/RAG/CoT）+ 概率重排 + Judge 协作，整套管线具有较强的工程可实现性，且每步都有对应评估。
- 实验设计严谨：除传统 PR/BDR 外还引入变异测试、显著检验、消融与反例验证，尤其揭示 TOGLL 训练数据泄漏，为领域内对比方法建立了更高的实证标准。

**潜在争议**：
- 多视角框架带来 token 开销与运行时间显著增加，是否在实际 CI/CD 或大规模项目中可接受仍有待观察。
- LLM-as-a-Judge 本身可能带有自身偏好偏见，论文未进行独立的人类共识一致性实验，因此最终断言选择的可靠性仍依赖内部评估协议。
- “整体式”模型若未来足够强，可能不再需要如此复杂的多智能体结构；但论文展示的方法仍可作为可解释、可控的工程化替代方案。

**总体评价**：AssertMate 是断言生成领域一项系统性较强的工程创新研究，以“分解 + 聚合”为核心，显著推动了 LLM 在测试预言生成中的实用性，并为后续研究提供了可复用的架构、数据集与公平性检验范式。尽管存在成本与泛化层面的局限，其研究成果对软件测试自动化和大模型应用均有明确价值。
