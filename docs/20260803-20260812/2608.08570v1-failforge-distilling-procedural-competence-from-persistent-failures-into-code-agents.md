## 摘要
拒绝采样微调（RFT）被广泛用于训练代码智能体，其方法是在可验证的软件工程任务上生成轨迹，保留通过测试的轨迹，并在成功的rollout上进行微调。然而，即使是强大的代码智能体也会在相当一部分此类任务上反复失败，而标准RFT只是简单丢弃这些失败样本。被丢弃的样本恰恰是最困难、信息量最大的样本，它们来自成本高昂的可验证实例。更强的基座模型可能会减少失败数量，但剩余的困难案例仍然定义了进一步改进的前沿。我们提出FailForge，一个将失败的rollout转化为训练信号的智能体框架。对于每个失败的实例，智能体根据错误反馈和执行轨迹诊断失败原因，将诊断提炼为简洁可操作的技能，并将该技能注入智能体上下文以进行有指导的第二次尝试。在技能指导下成功的轨迹被重新纳入RFT语料库。关键在于，训练时技能被移除，因此模型内化恢复的行为，而不是在推理时依赖外部提示。FailForge以极小的额外成本恢复了超过26%先前失败的实例，并在增强语料上训练Qwen3.5-4B，使SWE-bench Verified解决率相对于强RFT基线提升了6.6个百分点，且提升集中在最困难的问题上。

## Abstract
Rejection sampling fine-tuning (RFT) is widely used to train code agents by generating trajectories on verifiable software engineering tasks, retaining those that pass the tests, and fine-tuning on the successful rollouts. However, even strong code agents repeatedly fail on a substantial fraction of such tasks, and standard RFT simply discards these failures. The discarded samples are precisely the hardest and most informative ones, drawn from verifiable instances that are costly to curate. Stronger base models may reduce the number of failures, but the remaining hard cases still define the frontier for further improvement. We propose FailForge, an agentic framework that converts failed rollouts into training signal. For each failed instance, an agent diagnoses the failure from error feedback and execution traces, distills the diagnosis into a concise and actionable skill, and injects the skill into the agent context for a guided second attempt. Trajectories that succeed under skill guidance are folded back into the RFT corpus. Crucially, the skill is removed at training time, so the model internalizes the recovered behavior rather than relying on external hints at inference. FailForge recovers over 26% of previously failed instances at marginal additional cost, and training Qwen3.5-4B on the augmented corpus improves the SWE-bench Verified resolve rate by 6.6 points over a strong RFT baseline, with gains concentrated on the hardest problems.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：大规模语言模型（LLM）智能体在真实软件工程（SWE）任务上取得了显著进步，能够自主浏览仓库、编辑代码并通过执行验证修复。训练此类智能体越来越依赖**拒绝采样微调（RFT）**——在可执行环境中采样多条轨迹，仅保留通过隐藏测试的轨迹作为训练数据，其余废弃。
- **核心问题**：RFT存在**结构性低效**——在所有采样轨迹都失败的任务上，RFT完全无法产出任何训练信号，而这类任务恰恰是模型能力前沿上**信息量最大、最应当学习**的样本。单纯增加采样预算（从5倍到10倍）只能恢复很少一部分失败任务，说明这些持续失败反映的是**缺失能力**而非采样方差。
- **关键观察**：许多持续失败并非源于对特定实例知识的缺失，而是源于**可迁移的程序性能力（procedural competence）**的缺失，例如如何在大仓库中定位故障、如何解读复杂测试夹具、如何构建高效调查流程。
- **整体含义**：论文提出将失败的rollout转化为训练信号，从而在标准RFT丢弃的困难实例中回收高价值监督，推动模型在能力前沿上继续进步。

### 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

**核心思想**：FailForge通过五阶段pipeline，将标准RFT丢弃的持续失败实例转化为可训练监督信号：

1. **初始RFT与失败识别**：对任务池 D 中每个任务采样 K 条教师轨迹，通过测试的构成初始语料 C，全部失败的构成持续失败集 F。
2. **智能体技能归纳（Agentic Skill Induction）**：对每个失败实例 xi ∈ F，调用诊断智能体 A，输入失败轨迹、测试输出和推理痕迹、以及金标准补丁 pi，生成结构化技能 si。技能遵循四部分固定架构：
   - **适用条件（Applicability）**：何时该技能适用；
   - **关键原则（Key Principles）**：正确修复必须遵守的不变量；
   - **常见陷阱（Common Pitfalls）**：可能导致类似失败的做法；
   - **推荐方法（Recommended Approach）**：有序的调查和修复流程。
   
   技能被刻意表述为**方法论层面**、与具体仓库或bug无关的策略性指导，而非解决方案本身。
3. **泄漏过滤（Leakage Filtering）**：在离线数据构建中，金标准补丁可能将解决方案特定信息泄漏进技能。使用独立的法官模型 J 对每对（si, pi）进行**重建测试**：若能从技能中重建补丁（通过复制标识符、镜像控制流结构、指示特定修复步骤），则判定为泄漏并重新生成，直到通过或达到重试上限。法官模型的判断与人类标注者共识的一致性达到 96.7%（Cohen's κ = 0.805）。
4. **技能引导的重新rollout**：将技能 si 注入教师上下文（如写入 CLAUDE.md 或系统提示），重新采样 K 条引导轨迹，保留通过验证的轨迹，形成恢复语料 ˜C。
5. **技能移除与训练**：训练前通过移除算子 ρ 将技能文本从恢复轨迹中剥离，保留智能体自身的动作和推理。在原始语料与恢复语料的并集上微调学生策略，优化目标为：
   
   L(θ) = −Σ(xi,τ)∈C log πθ(τ|xi) − Σ(xi,˜τi)∈˜C log πθ(ρ(˜τi)|xi)

   这样模型被迫将技能条件下恢复的行为**内化到权重中**，而非在推理时依赖外部提示。

- **显著性能提升**：FailForge在SWE-bench Verified上达到66.2 pass@1，比强RFT基线高**+6.6点**，在pass@3和pass@5上均一致提升+3.0点；9B模型从63.6提升到67.2 pass@1；
