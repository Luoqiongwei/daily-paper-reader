## 摘要
数据是现代企业和机构的核心资源，数据错误在数据管道中传播会对生产造成严重影响。因此，数据验证对于确保下游应用的可靠性至关重要。这促使了数据单元测试的发展，即可执行程序，在数据通过大型数据管道传输之前对数据进行测试。然而，现有框架仅从观测数据中推导数据单元测试，忽略了消费下游数据的代码的语义。为此，我们提出了PrismaDV，一个复合AI系统，通过联合分析数据和下游任务代码，为表格数据综合生成任务感知的数据单元测试。PrismaDV将测试生成分解为多个由LLM驱动的步骤：数据剖析、列访问检测、任务代码中的数据流分析以及隐式数据假设的推断。随后，它为数据单元测试综合代码，并维护一个内部的“数据-代码假设图”，将生成的数据约束与任务的源代码关联起来。我们通过一个基于交互式Web的界面演示PrismaDV，参会者可以在五个真实世界数据集和60个下游任务上运行该系统，综合、检查和优化关于数据的自然语言假设以及可执行的数据约束。该界面允许参会者导航数据-代码假设图，在错误数据批次上对比任务感知数据单元测试与任务无关基线的差异，并交互式地编辑假设和数据约束。此外，参会者可以观察自定义提示优化器如何随时间适应特定数据集。

## Abstract
Data is a central resource for modern enterprises and institutions, and data errors propagating through data pipelines lead to serious impact in production. Therefore, data validation is essential for ensuring the reliability of downstream applications. This led to the development of data unit tests, executable programs that test data before moving it around through large data pipelines. However, existing frameworks derive data unit tests from observed data alone, ignoring the semantics of the code that consumes the data downstream.   To this end, we present PrismaDV, a compound AI system that synthesizes task-aware data unit tests for tabular data by jointly analyzing data and downstream task code. PrismaDV decomposes the test generation into multiple LLM-powered steps: data profiling, detection of column accesses, data flow analysis in the task code, and the inference of implicit data assumptions. It subsequently synthesizes code for the data unit test, and maintains an internal ``data-code assumption graph'' that links generated data constraints back to the task's source code.   We demonstrate PrismaDV through an interactive web-based interface where attendees run the system on five real-world datasets with 60 downstream tasks, synthesize, inspect and refine both natural language assumptions about the data and executable data constraints. The interface allows attendees to navigate the data-code assumption graph, compare task-aware data unit tests against task-agnostic baselines on erroneous data batches, and interactively edit assumptions and data constraints. Furthermore, attendees can observe how a custom prompt optimizer adapts the system to specific datasets over time.

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 核心思想
- 将数据单元测试生成视为一个**多步骤的复合 AI 流程**，每步由 LLM 驱动，逐步将输入（数据样本 + 任务源代码）转化为可执行的数据约束。
- 创新点在于**引入下游代码的语义**：通过数据流分析识别代码对哪些列进行操作、在哪些行进行了什么转换，从而推断出代码作者“内嵌”的隐式数据假设，再将其转化为可执行的测试。

### 2.2 总体架构与主要步骤

系统包含以下步骤（如图 1 所示）：

1. **数据剖析与列访问检测（Data Profiling & Column Access Detection）**  
   - 对数据样本计算轻量级 profile（如 null 率、唯一值、值分布等），作为后续步骤的上下文。  
   - 基于任务代码、任务文本描述、列名及 profile，利用 LLM 判断任务实际访问或依赖的列子集。  
   - 该模块可处理复杂的 SQL 查询（如 `SELECT *` 带 `EXCLUDE`）或非平凡的代码逻辑，避免静态字符串匹配的局限。

2. **数据-代码假设图的构建（Data-Code Assumption Graph）**  
   - 针对每个已访问列，执行**数据流分析**，标注代码中对该列或其派生数据进行操作的源代码行号。  
   - 由 LLM 推断假设对象列表，每个假设包含：  
     - 自然语言描述（如“email 列必须是合法邮箱地址”）；  
     - 涉及的列；  
     - 促使该推断的源代码行引用。  
   - 这些假设共同构成**数据-代码假设图**，将数据列、代码行、假设和后续生成的约束连接起来。

3. **约束代码合成（Constraint Code Synthesis）**  
   - 将每个假设与任务代码、任务描述、访问列列表、目标框架（Deequ 或 Great Expectations）的 API 摘要一起交给 LLM，生成可执行约束代码。  
   - 约束实现布尔函数，例如检查数据样本上的聚合统计量是否满足既定阈值。

4. **后处理（Post-processing）**  
   - 过滤掉无法被 Deequ/GE 解析的约束，以及当前数据样本上不通过的约束，最终形成可部署的数据单元测试。

## 6. 主要结论与发现

- **任务感知数据验证效果显著优于任务无关验证**：联合分析数据与下游代码，可以让数据单元测试更贴合实际消费场景，从而大幅提升误报数据批次的识别准确率，尤其是召回率（从基线的 42.7% 提升至 86.6%）。

- **提示优化可持续改善系统**：根据真实执行反馈迭代 prompt，可以减少误报警并适应特定领域的数据分布，提升测试长期稳定性。

- **隐私与安全风险未讨论**：系统需要将数据样本和下游任务源代码发送至商用 LLM（如 gpt-5、gemini-2.5-pro），在涉及敏感数据（如个人隐私、企业机密）的部署场景中存在数据泄露风险；论文未讨论本地化模型部署、脱敏预处理或私有化 LLM 的适配方案。

- **评估指标偏重检测层面**：Precision/Recall/F1 仅度量“坏批次是否被测试拦截”，但未测量系统生成的数据单元测试在实际生产管道中的误报警率、每次误报的人工处置成本、测试在不同时间窗口上的稳定性，以及对下游任务真正造成破坏的端到端减少程度。

- **交互式精炼依赖用户专业能力**：演示中用户可编辑或新增自然语言假设，但这一过程需要用户具备一定数据工程与领域知识；论文未评估不同经验水平的用户在使用系统后产出质量的差异，也未提供新手引导或自动建议机制。

- **工作流范围有限**：系统聚焦于“批式数据表 + 下游代码”的验证场景，未覆盖流式数据、增量数据验证、多表 join 或依赖链中多任务串联引发的一致性问题；这些场景在真实工业实践中同样常见，但系统支持尚不明确。

## 9. 总体评价

PrismaDV 以任务感知的方式重新定义数据单元测试的生成范式，将下游代码的隐式数据假设转化为可执行、可溯源、可交互精炼的约束，在方法创新、系统设计和可用性上都达到了较高水准。其核心贡献在于证明了 LLM 驱动的复合 AI 流程能够弥合“数据分布”与“数据消费语义”之间的鸿沟，这与当前仅依赖数据统计的验证工具形成了本质区别。然而，作为一篇演示论文，其定量证据仍显单薄，许多关键能力（如复杂代码鲁棒性、优化闭环收益、生产环境长期稳定性）尚未被充分验证。总体而言，这是一项思想前瞻、实现完整、表达清晰的研究，具有明显的工具化落地潜力，也为后续的数据质量验证研究开辟了“代码感知”这一重要方向。
