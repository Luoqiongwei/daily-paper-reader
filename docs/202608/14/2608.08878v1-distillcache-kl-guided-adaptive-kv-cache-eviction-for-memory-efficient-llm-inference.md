## 摘要
基于Transformer的大语言模型（LLM）在许多任务上表现出色，但其键值（KV）缓存随序列长度线性增长，给长上下文推理带来了严重的内存瓶颈。现有的启发式驱逐方法（如H$_2$O和SnapKV）依赖静态注意力或位置信号，往往无法捕捉标记对未来的预测影响力。我们提出DistillCache，一个强化学习框架，将KV缓存驱逐建模为顺序决策问题。DistillCache利用丰富的模型内部信号（注意力统计、值范数、熵和位置）学习轻量级策略网络，并通过REINFORCE结合逐KL散度奖励进行训练，以保持完整缓存的输出分布。在一个7B参数量的指令微调Transformer（Mistral-7B-Instruct-v0.3）上，DistillCache在25%缓存预算下保留了LongBench上94.2%的完整缓存准确率，在长上下文任务上分别超越强启发式基线（H$_2$O、SnapKV）最多2.7个绝对百分点，并在我们的重新实现中超越并发的基于RL的方法（ForesightKV、RLKV）最多1.4个百分点。在推理基准上，DistillCache与最佳并发方法相当，并在激进压缩下超越它。它还提供了高达2.1倍完整缓存吞吐量，同时保持有竞争力的实际效率。这些结果凸显了学习型、分布感知策略在内存高效的长上下文LLM推理中的有效性。

## Abstract
Transformer-based large language models (LLMs) achieve strong performance across many tasks, but their Key-Value (KV) cache grows linearly with sequence length, creating a severe memory bottleneck for long-context inference. Existing heuristic eviction methods (e.g., H$_2$O and SnapKV) rely on static attention or positional signals that often fail to capture a token's future predictive influence. We propose DistillCache, a reinforcement learning framework that formulates KV-cache eviction as a sequential decision problem. DistillCache learns a lightweight policy network using rich internal model signals (attention statistics, value norms, entropy, and position) and trains it with REINFORCE via a per-step KL-divergence reward to preserve the full-cache output distribution. On a 7B-parameter instruction-tuned Transformer (Mistral-7B-Instruct-v0.3), DistillCache retains 94.2% of full-cache accuracy on LongBench at a 25% cache budget, outperforming both strong heuristic baselines (H$_2$O, SnapKV) by up to 2.7 absolute points and, under our re-implementations, concurrent RL-based methods (ForesightKV, RLKV) by up to 1.4 points on long-context tasks. On reasoning benchmarks, DistillCache is competitive with the best concurrent method and surpasses it under aggressive compression. It also delivers up to 2.1x full-cache throughput while maintaining competitive practical efficiency. These results highlight the effectiveness of learned, distribution-aware policies for memory-efficient long-context LLM inference.

## 1. 核心问题与整体含义（研究动机和背景）

- **KV 缓存内存瓶颈**：Transformer 大语言模型在自回归解码时依赖 KV 缓存避免重复计算，但缓存随序列长度线性增长，成为长上下文推理的核心内存瓶颈。
- **现有启发式方法的不足**：H₂O 基于累计注意力（"heavy hitters"）、SnapKV 基于滑动窗口聚类、StreamingLLM 固定保留 attention sinks 和最近窗口、Keyformer 基于注意力熵——这些方法依赖静态注意力或位置信号，使用固定的评分规则。
- **核心局限性**：静态评分假设"过去的注意力模式能可靠预测未来的词元效用"，但在长程依赖、结构化推理或多跳问答中，词元的重要性取决于下游生成后果，静态信号难以捕捉。
- **问题本质**：如何在固定内存预算下，选择保留哪些 KV 词元，以使压缩后模型的下一次词元分布尽可能接近完整缓存模型的分布——本质上是一个受预算约束的序贯决策问题。

## 2. 方法论：核心思想、关键技术细节、公式与算法流程

### 2.1 核心思想
- 将 **KV 缓存驱逐建模为序贯决策问题**：每一步解码时，策略网络观察缓存中每个词元的特征，决定保留哪些词元，收到基于全缓存/剪枝缓存分布 KL 散度的奖励。
- 与启发式方法不同，DistillCache **直接优化下游分布保真度**，而非使用注意力统计作为代理信号。
- 目标：在每一解码步保留预算内词元子集，使剪枝模型的下一词元分布 P̂_t 尽量接近全缓存模型分布 P_t。

### 2.2 状态空间（5 维特征向量）
对缓存中每个词元 token i，构造特征向量 x_i = (α_i, ‖v_i‖₂, σ_i, H_i, pos_i) ∈ ℝ⁵：

- **α_i**：词元 i 作为 key 在所有头和层中收到的平均注意力质量（全局显著性）；
- **‖v_i‖₂**：值向量的 ℓ2 范数；
- **σ_i**：词元 i 跨头收到的注意力质量方差；
- **H_i**：注意力加权平均熵——衡量近期查询（窗口 w=64）对词元 i 的注意力上下文的集中程度（低 H_i = 被集中查询选中；高 H_i = 在弥散注意力下被选中）；
- **pos_i**：缓存中的归一化序列位置。

### 2.3 动作空间
- 轻量 MLP 策略 f_φ（两层、128 隐藏单元、LayerNorm，约 200K 参数）为每个词元输出标量分数 s_i = f_φ(x_i)。
- **训练时**：添加 i.i.d. Gumbel 噪声，s̃_i = s_i + g_i，取 top-B，产生 Plackett–Luce 分布的随机子集采样。
- **推理时**：确定性取 top-B，不加噪声。

### 2.4 过渡动力学与训练架构
- **Teacher cache**：永不剪枝，计算全缓存分布 P_t。
- **Student cache**：每步按策略剪枝并追加新 KV 对，计算剪枝分布 P̂_t。
- 注意：训练时双缓存使内存开销翻倍，但训练为离线进行；推理时仅单次前向传播，剪枝只影响下一步而非当前预测。

### 2.5 奖励设计及其理论基础
- 奖励定义为：R_t = −D_KL(P_t ‖ P̂_t)。
- **理论动机**：通过三角不等式得出 ‖o_t − ô_t‖₂ ≤ 2Cε_t（ε_t 为被驱逐注意力质量，C 为值向量范数上界）；再经 logit 线性投影与 softmax 局部 Lipschitz 连续性，证明 D_KL(P_t‖P̂_t) ≤ (2C′²ε_t²)/σ_min²，其中 σ_min 为最小 softmax 概率——即**逐 KL 散度被被驱逐注意力质量的平方所约束**，为奖励奠定理论依据。KL 奖励端到端地通过完整 softmax 捕捉保留词元间的非线性交互。

### 2.6 策略优化
- 使用 **REINFORCE** + 熵正则化 + 方差缩减基线（RLOO leave-one-out + 指数移动平均基线）。
- 梯度形式：∇J = E[Σ ∇log π_φ(a_t|s_t)(G_t − b_t)] + β ∇E[H(π_φ(·|s_t))]；
- 超参数：γ=0.99，β=0.01；
- Gumbel-Top-B 的 log 概率可从 Plackett–Luce 子集分布解析导出，log 配分函数用 O(L·B) 时间复杂度动态规划精确计算；
- 熵项用单样本代理 Ĥ ≈ −log π_φ(a_t|s_t)。

### 2.7 推理流程（Algorithm 1）
- 初始缓存为空，逐步前向传播 → 提取特征 → 策略打分 → top-B 确定性选择 → 剪枝缓存供下一步使用；当前 token 从未剪枝前向传播的 logits 中贪婪解码。无硬编码保护（sink token 和最近 token 的保护是学出来的）。

## 6. 主要结论与发现

- **核心结果**：在 Mistral-7B-Instruct-v0.3 上，25% 缓存预算下 LongBench 保留 **94.2%** 全缓存精度（39.1 vs 41.5），较 H₂O 提升 2.7 个绝对点，较并发 RL 方法提升 0.9–1.4 个点；12.5% 激进预算下 LongBench 达 88.2%，优势更大。
- **推理任务**：RLKV 在中等预算（50%/25%）下略强（+0.3～+0.7 点），DistillCache 在 12.5% 预算下反超（39.9 vs 38.9，+1.0 点）。
- **跨模型泛化**：零样本从 Mistral-7B 迁移到 Llama-3-8B，无需重训练即超越两种启发式基线（LongBench 38.4 vs H₂O 37.2、SnapKV 37.9），而出色的并发 RL 方法需重训练。
- **长上下文优势**：8K 上下文下 DistillCache 优势最显著（38.1 vs ForesightKV 37.0、RLKV 36.4），显示逐分布保真的韧性。
- **困惑度**：25% 预算下 PPL 增量仅 +0.35（最低），对应 H₂O +0.62、SnapKV +0.55、ForesightKV +0.44、RLKV +0.47。
- **吞吐**：约 2.1× 全缓存吞吐，与并发 RL 方法相当，略低启发式方法。
- **学习行为**：无硬编码保护地学到保留 attention sink 和最近词元（复现 StreamingLLM/H₂O 模式），并额外保留逻辑关键词元（否定词"not"、从句动词"say"）；保留分布比启发式方法更均匀地覆盖中段位置。
- **消融结论**：RL 优化本身带来超越监督排名器的增益（39.1 vs 37.8），特征丰富性也有效果，联合作用最强；KL 奖励优于长期贡献/全局排名奖励。
- **混合潜力**：与 RLKV 头级门控混合获得 +0.7 进一步提升，说明两种方法互补。

## 7. 优点

- **直接优化因果标准**：用全缓存/剪枝缓存分布间的逐 KL 散度作为奖励，与下游生成质量直接对齐，而非代理指标；
- **理论支撑完整**：从注意力质量驱逐界推导出 KL 上界，为奖励设计提供严密的数学基础；
- **特征设计富有洞察**：融合注意力质量、值范数、注意力方差、注意力加权熵和位置，其中基于注意力的熵特征（H_i）能区分"被集中查询选中"与"在弥散注意力下被选中"的词元，信息丰富；
- **精确策略梯度**：通过动态规划对 Plackett–Luce 配分函数精确计算 O(L·B)，避免蒙特卡洛近似方差，数学上优雅且实现可微；
- **训练/推理架构合理**：教师-学生双缓存保证训练因果一致性，推理仅需单次前向传播，剪枝不干扰当前预测，无硬编码保护；
- **泛化性好**：零样本跨模型迁移表明策略学到的是通用缓存重要性模式而非过拟合特定模型；
- **统计规范**：5 种子的均值±标准差一致；明确区分官方与重新实现基线，对公平性问题有自觉；
- **正交、可组合**：与头部级剪枝（RLKV）、系统级压缩（offloading、PagedAttention 等）互补，混合验证有增益；
- **报告全面**：包括错误模式分解、逐任务细分、响应长度分析、训练动态、保留位置分布等，支撑高。

## 8. 不足与局限

- **训练成本高**：约 130 GPU-小时 + 训练时双缓存内存翻倍，远超免训练启发式，针对大型模型的扩展性存疑；
- **REINFORCE 方差**：尽管有熵正则化、RLOO 基线和多种子平均，仍比 PPO/GRPO（ForesightKV/RLKV 所用）方差高，训练稳定性有风险；
- **推理处理开销**：+1.4 ms/token 的特征提取+策略评估，比 H₂O 慢，实际吞吐略低于启发式方法（38.0 vs 42.8 tokens/s）；
- **并发基线公平性**：ForesightKV 和 RLKV 为按描述重新实现，非官方代码库，原始设置/超参数差异可能影响差距的准确性；
- **特征范围有限**：策略独立评分每词元，未显式建模词元间交互；特征依赖 Transformer 注意力模式，迁移到非 Transformer 架构（如 Mamba、RWKV）需重新设计；
- **推理任务短板**：RLKV 在推理任务中等预算下仍较强（ForesightKV 在单文档 QA 领先，RLKV 在代码完成领先）；
- **上下文长度限制**：最长仅评估 8K 上下文，未覆盖 32K–128K 的极端长上下文场景；
- **模型规模范围有限**：仅 7B 和 8B 模型，缺少 13B+ 实验验证；
- **量化评估不完整**：精度数字相对低（40 分左右），实际应用中生成质量的客观评估需要更多任务语料支撑；
- **需要每模型训练（或跨模型降精度）**：零样本迁移精度有下降（LongBench 39.1→38.4），显著跨模型性能需针对性训练，维护成本高。
