## 摘要
由大语言模型（LLM）驱动的编程智能体在自动化软件工程任务方面已取得快速进展，但仓库级问题解决仍然具有挑战性。除了生成看似合理的补丁之外，智能体还必须跨相互依赖的文件定位相关代码，并维护既充分又聚焦的仓库上下文。代码图能够揭示非局部关系，但线性文本接口掩盖了其拓扑结构；渲染完整仓库图会得到过于稠密、难以可靠感知的视觉表示，而一次性的局部视图会随着探索的推进而变得过时。我们提出 RepoAtlas，一个无需训练的模块，它通过仓库代码图上的“选择--投影--刷新”循环来维护不断演化的多模态仓库视图。RepoAtlas 结合来自问题的证据与智能体当前的探索状态，在固定预算下选择与任务相关的区域，将所选结构投影为互补的视觉和文本表示，并在探索状态的变化使其过时时刷新视图。我们在 SWE-bench Verified 上评估 RepoAtlas，相对于最强的多模态图基线，它将解决率提高了 2.4 个百分点，同时将输入 token 和模型调用平均减少了 5.8% 和 7.8%，并且在三个不同家族和规模的模型上均取得了一致增益。

## Abstract
Large language model (LLM)-powered coding agents have made rapid progress in automating software engineering tasks, yet repository-level issue resolution remains challenging. Beyond generating a plausible patch, an agent must localize relevant code across interdependent files and maintain repository context that is both sufficient and focused. Code graphs expose non-local relations, but linear text interfaces obscure their topology; rendering the full repository graph yields visual representations that are too dense to perceive reliably, whereas a one-shot local view becomes stale as exploration proceeds. We present \textbf{RepoAtlas}, a training-free module that maintains evolving multimodal repository views through a \emph{select--project--refresh} loop over a repository code graph. RepoAtlas combines evidence from the issue with the agent's current exploration state to select a task-relevant region under a fixed budget, projects the selected structure into complementary visual and textual representations, and refreshes the view when changes in the exploration state render it outdated. We evaluate RepoAtlas on SWE-bench Verified, where it improves the resolve rate by 2.4 points while reducing input tokens and model calls by 5.8\% and 7.8\% on average, relative to the strongest multimodal graph baseline, with consistent gains across three models of different families and scales.

## 1. 核心问题与研究动机

- **背景**：LLM 驱动的编程智能体在自动化软件工程任务上进展迅速，但**仓库级问题修复（repository-level issue resolution）**仍是难点。
- **核心困难**：智能体不仅要生成合理补丁，还需：
  - 跨相互依赖的文件**定位相关代码**；
  - 维护**既充分又聚焦**的仓库上下文（证据逐步显现、分散于轨迹、重要性随焦点漂移）。
- **现有方案的矛盾**：
  - 线性文本接口掩盖代码图拓扑，迫使智能体从逐条关系里重建全局结构；
  - 渲染完整仓库图过于稠密，视觉语言模型（VLM）难以可靠感知；
  - 一次性局部视图会随探索推进而**过时**。
- **核心问题**：如何为仓库级编码智能体维护一种**紧凑、结构化、且随探索演化**的仓库视图。
- **整体含义**：论文把"仓库上下文构建"重新表述为**演化视图维护（evolving view maintenance）**问题，并提出"选择–投影–刷新"框架统一回答三个问题——保留什么、如何呈现、何时更新。

## 2. 方法论

### 2.1 整体思想

- RepoAtlas 是**免训练（training-free）**模块，在离线构建一次的仓库代码图上，通过 **Select → Project → Refresh** 闭环维护动态多模态视图。
- 视图形式化：`G_t = (V_t, E_t, M_t)`，受预算 `B = (B_V, B_E)` 约束（默认 `B_V=15` 节点、`B_E=20` 边）。`(V_t, E_t)` 为结构内容，`M_t` 为呈现规格（粒度、聚合、图文分配）。视图**不必是 G 的字面子图**。

### 2.2 离线仓库图

- 有向类型化图 `G = (V, E, τ_V, τ_E)`：
  - 节点：module / class / callable / variable，含限定名、签名、精确源码位置；
  - 边：结构关系（contains、inherits）+ 语义依赖（calls、imports、overrides、symbol use）。

### 2.3 阶段 A：预算化结构选择

- **任务条件相关性**由三类证据构成：词汇（issue 与标识符匹配）、语义（issue 与实体嵌入相似度）、轨迹（当前探索焦点），均校准到统一尺度。
- 采用**逐节点取最大值**融合（式 1），避免多个弱信号压倒一个强匹配：`a_t(v) = max(a_lex, a_sem, a_traj)`。
- 构建行随机转移矩阵 P，做**个性化 PageRank**（式 2）传播相关性，扩散到 issue 未直接命名的依赖实体；最终相关性再取一次逐节点最大值（式 3 前）以保留被扩散衰减的强直接证据。
- **连通结构构建**：在预算下搜索连通区域最大化相关性和（式 3），必要时引入**超节点（supernode）**，并通过**代表性暴露（representative exposure）**将每个超节点的最高分成员作为具体节点暴露，保留精确源码位置。

### 2.4 阶段 B：自适应多模态投影

- 视觉表示暴露拓扑、分组、边方向/类型、跨文件连接；文本表示保留标识符、类型、签名、源码位置；两者**对齐**，用稳定引用键关联。
- **自适应投影**：根据 `(V_t, E_t)` 拓扑与探索状态 `s_t`，选择视图形式（力导向、层次、流程图）、布局、标签粒度与模态分配；投影**只改呈现、不改内容**，同一 `(V_t, E_t)` 的不同投影内容等价。

### 2.5 阶段 C：状态感知刷新

- 探索状态：`s_t = (F_t, C_t, G_{t-1}, φ_t)`，`φ_t ∈ {Localize, Edit, Test}`。
- **复用或刷新决策**：由显式请求或主动检查触发；仅当当前视图对当前阶段覆盖不足时重跑选择与投影。
- **阶段条件刷新**：
  - Localize：维持多模态视图，issue 描述始终作为选择证据；
  - Edit：首次实质编辑后，替换为聚焦修改代码及其结构影响的**文本视图**（视觉上下文在编辑阶段收益低且可能分散注意）；
  - Test：反馈与当前工作范围一致则保留视图，改变影响范围则刷新；若原阶段范围仍有效则恢复，否则回到 Localize。
- 为控制视觉上下文开销，只保留**当前一张视觉图**，刷新时替换，同时文本索引保留已识别代码位置。

## 6. 主要结论与发现

- **效果**：RepoAtlas 在三个模型上均取得最高解决率：
  - Qwen3.6-35B-A3B：63.1%（较最强基线 +1.6pp），输入 token −7.9%，调用 −8.2%；
  - MiMo-V2.5：68.0%（+1.1pp）；
  - Kimi-K2.5：72.4%（+3.0pp）；
  - 平均 +2.4pp，输入 token −5.8%、调用 −7.8%，API 成本分别降低 6.9%、2.9%、2.4%。
- **效率来源**：有界上下文管理——初始视图即给出候选区域与代码位置，缩短搜索读取迭代；平均每实例仅 **2.43 个视图**，刷新替换图像而非累积。
- **消融结论**：视觉与文本通道**互补**（去视觉 −1.9pp，去文本 −3.9pp）；固定布局 −2.7pp；无刷新 −4.7pp，每调用刷新降至 51.0% 且开销最高；无预算 −3.3pp（主要影响视觉密度而非交互成本）。
- **选择结论**：PageRank 传播与代表性暴露**互补**；去掉代表性暴露使 FR 从 0.252 骤降至 0.102，说明超节点内金标函数必须被暴露为具体节点。
- **失败发现**：静态图无法捕获**仅运行时注册的依赖**（sympy-17630），导致刷新反复收窄到错误区域。

## 7. 优点

- **问题重构清晰**：把仓库上下文构建统一表述为"演化视图维护"，三阶段框架与三个挑战一一对应，逻辑自洽。
- **免训练、易集成**：不改基础模型架构、不需任务特定训练，可直接插拔到现有智能体。
- **选择阶段设计有原则**：词汇/语义/轨迹三源证据 + 逐节点最大值融合（保精度）+ 个性化 PageRank（补依赖）+ 超节点与代表性暴露（在固定预算内兼顾覆盖与可操作性）。
- **内容与呈现解耦**：投影只改布局/粒度/模态分配而不改结构内容，保证不同呈现内容等价，便于受控比较。
- **阶段感知刷新贴合认知需求**：Localize 用多模态、Edit 转文本、Test 按反馈决策，符合"视觉在定位阶段更有用"的已有发现。
- **评估同时覆盖效果与效率**：除解决率外报告 token、调用与真实 API 成本，且在同模型内比较，较为严谨。
- **诚实报告失败案例**：明确指出静态图局限，并给出未来方向。

- **预算固定**：主实验固定 `B_V=15`、`B_E=20`，敏感性分析置于附录，正文未展示预算对结果的完整影响曲线。
