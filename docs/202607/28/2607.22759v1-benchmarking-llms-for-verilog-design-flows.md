## 摘要
大型语言模型（LLM）在代码生成方面展现出潜力，但它们生成正确、可综合的硬件描述语言（HDL）代码的能力仍需要适当的基准测试。现有的评估主要依赖pass@k指标，且缺乏完整的端到端工具链验证。本文提出了一个可重复的基准测试平台，该平台在50个精心设计的任务（包括组合、时序、有限状态机（FSM）和混合设计）上评估开源LLM的Verilog RTL生成能力。该流水线由约束提示、后处理、基于波形分析和语义感知的迭代优化、形式等价性验证以及基于抽象语法树（AST）的修复组成，通过Verilator编译和Icarus Verilog仿真验证生成的代码。在12个基准测试和总共1610次运行中，评估了三种不同规模的模型（Llama-3-8B、StarCoder2-7B和TinyLlama-1.1B），该流水线将三个开源模型的语法有效性从0%提升至平均70.43%，仿真通过率提升至51.8%。值得注意的是，TinyLlama（1.1B参数）实现了最高的个体语法有效性（80.0%），其功能正确性与8B模型相当。该平台和数据集是开源的，使得生成式AI在硬件设计工作流中的可重复评估成为可能。

## Abstract
Large language models (LLMs) show promise in code generation, but their capabilities to produce correct, synthesizable hardware description language (HDL) code still remain to be properly benchmarked. Existing evaluations are primarily relying on pass@k metrics and lack proper end-to-end toolchain validation. This paper presents a reproducible benchmarking platform that evaluates open-source LLMs on Verilog RTL generation across 50 curated tasks consisting of combinational, sequential, finite state machine (FSM), and mixed designs. The pipeline consisting of constrained prompting, post-processing, and semantic-aware iterative refinement with waveform analysis, formal equivalence verification, and Abstract Syntax Tree (AST)-based repair validates the generated code via Verilator compilation and Icarus Verilog simulation. Across the 12 benchmarks and the 1,610 total runs evaluating three models of different sizes (Llama-3-8B, StarCoder2-7B, and TinyLlama-1.1B), the pipeline improved syntax validity from 0% to a 70.43% average and simulation pass rate to 51.8% across three open-source models. Most notably TinyLlama (1.1B parameters) achieved the highest individual syntax validity at 80.0%, with functional correctness comparable to the 8B model. The platform and dataset are open-source, enabling reproducible evaluation of generative AI for hardware design workflows.

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：采用“受控生成”（Guarded Generation）流水线，将LLM生成的Verilog代码视为草稿，通过多阶段验证和修复确保其可编译、可仿真、可综合。
- **总体架构**：流水线包含五个渐进阶段（Phase 1-5），如图1所示：
  - **Phase 1（基线）**：简单few-shot提示，无约束、无后处理、无修复循环 → 语法有效率为0%。
  - **Phase 2（约束提示）**：在提示中注入精确模块名、完整端口列表（从 tasks.json 提取）、Verilog-2001语法约束（仅使用 wire/reg，禁止 always_ff 等）。
  - **Phase 3（后处理）**：`post_process_verilog()` 函数执行六项顺序变换：模块名修正、端口强制执行、 logic→wire/reg 转换、BSV伪影移除、时序归一化（Phase 3加入）、FSM/混合模板支架（Phase 4加入）。
  - **Phase 4（语义感知迭代修复）**：引入 generate→evaluate→feedback→regenerate 循环（最多5次迭代）。反馈生成器将编译器错误和测试台不匹配反馈给模型（≤500字符）。三种语义技术增强：
    - **波形分析器**：仿真参考设计和生成设计产生VCD文件，逐周期比较信号值，标记首个不匹配。
    - **形式验证器**：运行Yosys `equiv_make/equiv_simple`，捕捉测试台激励无法覆盖的逻辑错误。
    - **AST修复**：使用pyverilog解析生成的Verilog，进行正则无法处理的结构性修复（如缺失端口声明、未声明信号）。
    - **置信度追踪器**：计算token对数概率的Shannon熵；熵高时跳过昂贵的波形和形式步骤。
  - **Phase 5（FSM和混合增强）**：针对FSM和混合设计添加四项专门改进：
    - 在提示中嵌入显式状态转换表，替换自然语言描述。
    - 提供对比性正确/错误FSM示例，展示常见错误（缺失default、状态空间坍缩）。
    - 严格模式：禁用熵门控，确保每个FSM任务使用完整语义修复栈。
    - 微修复步骤：针对缺失default、不完整 begin/end、错误复位逻辑。
  - **任务分级**：将任务分为Tier 0（简单组合，单次迭代，无语义工具）、Tier 1（标准时序，最多5次迭代+波形+AST修复）、Tier 2（复杂FSM/混合，最多5次迭代+全语义栈+形式验证）。

## 6. 主要结论与发现

1. **工作流设计比模型规模更重要**：约束提示+后处理带来的语法有效性提升（0%→60%）大于任何模型间的差异。TinyLlama-1.1B在语法有效性上以80.0%领先，仿真通过率（60.7%）接近Llama-3-8B（59.3%），表明小型模型配合良好工作流也能达到竞争性结果。
2. **FSM和混合设计仍是难点**：即使经过Phase 5增强，FSM和混合设计的语法和仿真通过率仍远低于组合/时序。三个模型在复杂状态机任务上均不可靠。
3. **迭代修复对语法有效，但对FSM逻辑无效**：编译器错误反馈能可靠修复语法问题，仿真不匹配反馈对组合任务有效，但FSM状态转换错误（状态坍缩、Moore/Mealy混淆、缺失default导致综合阻塞）即使在5次迭代后仍无法根本修复。
4. **综合通过率**：BM12中66.7%的运行可综合，时序设计综合率最高（85.7%，平均5.0单元），FSM（43.1%）和混合（48.9%）最低。合成结果中StarCoder2-7B生成代码平均单元数最高（12.1），表明结构冗余。
5. **主要失败类型**：
   - 结构失败（BM1-2）：模块名/端口错误、SystemVerilog/BSV伪影 → 约束提示和后处理基本解决。
   - 时序失败（BM3-8）：缺失复位处理、不完整敏感列表致锁存器推断 → 模板支架解决。
   - FSM失败（BM7-12）：状态转换坍缩（如旋转门控制器不离开解锁状态）、Moore/Mealy时序错误、缺失default分支 → Phase 5增强部分缓解但未消除。
   - 混合失败：丢弃寄存输出阶段，仅实现组合路径。

## 8. 不足与局限

- **任务集范围有限**：仅包含单模块、全确定性测试台设计，缺乏层次化RTL、总线协议（如AXI）、多时钟域逻辑、复杂IP级设计，与实际生产环境差距大。
- **无后综合质量指标**：仅评估可综合性，未测量合成后的面积、时序、功耗（PPA）。作者提到这是未来工作，但当前结论无法保证生成的RTL在实际物理约束下可用。
- **测试台覆盖可能不足**：功能正确性由参考测试台定义，若测试台激励有限，可能导致伪通过率（FSM中缺失default分支但仍能通过仿真即为例）。
- **模型范围窄**：仅测试三个<8B参数的开源模型，未包含更大模型（如CodeLlama-34B、GPT-4）或领域微调模型，无法评估规模扩展或商业化方案的优势。
- **硬件非确定性方差**：即使温度0.0，σ在表III中明显（如TinyLlama仿真通过率60.7%±5.0%），归因于Apple Silicon推理硬件级非确定性。仅3次重复可能不足以完全捕获方差。
- **FSM修复效果有限**：尽管Phase 5增加了多种增强，FSM功能正确性仍较低，反馈信号不够精细，模型无法从波形差异中正确推断具体状态转换错误。
- **工具链局限**：仅使用开源工具链（Verilator、Icarus、Yosys），未验证工业级综合工具（如Synopsys DC）的行为。
