## 摘要
大型语言模型（LLM）通过自然语言提示生成代码，但现实中的提示很少提供完整的规范。当提示中未指定输入格式、错误处理或设计决策时，LLM会用隐含假设填补这些空白，这些假设决定了生成代码的行为和正确性。由于这些假设仍然隐藏，生成的代码可能在满足测试的同时违背开发者的意图。我们提出AssumptionMiner，一个将隐含假设作为基于LLM的代码生成中的第一类产物的框架。除了代码，AssumptionMiner还生成一个显式的假设层，它是推断的约束和设计决策的结构化表示，开发者可以检查、确认或修改。基于AST的依赖图能够仅重新生成受修改假设影响的代码。我们还引入了一个包含180个模糊编程任务和676个标注假设的基准，包括一个用于评估代码定位的人工验证子集。我们评估了假设提取、代码定位和假设引导的重新生成。在开源LLM上，一个置信度加权集成在假设提取上取得了0.816的F1分数，相比最强的离线基线提升了3.6倍。在人工验证的定位基准上，AST引导的定位比基于关键词和整个文件的基线识别出更精确的代码区域。在假设修正过程中，针对性重新生成比非针对性方法修改更少的代码，同时暴露出处理级联编辑的挑战。这些结果表明，使假设显式化提高了基于LLM的代码生成的透明度和可控性。

## Abstract
Large language models (LLMs) generate code from natural-language prompts, yet real-world prompts rarely provide complete specifications. When prompts leave input formats, error handling, or design decisions unspecified, LLMs fill these gaps with implicit assumptions that shape the generated code's behavior and correctness. Because these assumptions remain hidden, generated code may satisfy tests while violating developer intent. We present AssumptionMiner, a framework that makes implicit assumptions a first-class artifact of LLM-based code generation. In addition to code, AssumptionMiner produces an explicit assumption layer, a structured representation of inferred constraints and design decisions that developers can inspect, confirm, or revise. An AST-based dependency graph enables targeted regeneration of only the code affected by a revised assumption. We also introduce a benchmark of 180 ambiguous programming tasks with 676 annotated assumptions, including a human-verified subset for evaluating code localization. We evaluate assumption extraction, code localization, and assumption-guided regeneration. Across open-source LLMs, a confidence-weighted ensemble achieves an F1 score of 0.816 for assumption extraction, improving on the strongest offline baseline by 3.6x. On the human-verified localization benchmark, AST-guided localization identifies more precise code regions than keyword-based and whole-file baselines. During assumption revision, targeted regeneration modifies less code than non-targeted alternatives while exposing challenges in handling cascading edits. These results demonstrate that making assumptions explicit improves the transparency and controllability of LLM-based code generation.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：大型语言模型（LLM）从自然语言提示生成代码时，现实中的提示往往不完整，缺少输入格式、错误处理、设计决策等细节。LLM 会隐式地填补这些空白，产生“隐含假设”（implicit assumptions），导致生成的代码能通过单元测试却违背开发者的实际意图（即“working-but-wrong”问题）。
- **整体含义**：现有工具无法让开发者看到 LLM 究竟做了哪些假设，因此无法在代码偏离意图时及时修正。需要一种系统性的方法将隐含假设显式化、可审查、可追溯，从而提升 LLM 代码生成的透明度和可控性。

### 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：将隐含假设作为代码生成的一等输出，在生成代码的同时产生一个“假设层”（assumption layer），包含结构化的假设记录（AssumptionRecord），并通过 AST 依赖图将假设与代码区域关联，支持开发者审查、修改后用增量再生只更新受影响的代码部分。
- **关键技术细节**：
  - **假设提取**：使用两阶段提示（chain-of-thought + 结构化格式），让 LLM 首先推理代码中超出提示要求的设计决策，然后以 JSON 格式输出 AssumptionRecord（含类别、描述、替代方案、置信度、严重性等）。
  - **假设‑代码依赖图**：分为两轮构建——第一轮通过关键词重叠筛选候选 AST 节点，第二轮通过树‑手术（tree-sitter）自底向上回溯到最小包围子树，得到每个假设所控制的代码区域（CodeRef）。
  - **增量再生**：当开发者修改某个假设（如将 MD5 改为 bcrypt），只将受影响的代码子段加上上下文（±5 行）送入 LLM 重新生成，然后拼接到原代码中，其余部分保持不变。
  - **交互界面**：实现为 Web 面板，开发者可检查、接受、编辑或拒绝每条假设，并触发增量再生。

### 6. 论文的主要结论与发现

1. **提取能力**：置信度加权集成（Qwen32B + DeepSeek）在类别级匹配下达到 F1=0.816，是最好离线基线（F1=0.225）的 **3.6 倍**。但在更严格的决策级匹配下，最高 F1 仅为 0.662，说明准确识别具体决策仍远未解决。
2. **代码定位**：AST 引导的启发式映射在策展子集上比起关键词映射产生更紧凑的区域（平均 IoU 0.581 vs 0.545），阈值准确率相近（56.9% vs 60.6%）。LLM 引导映射器（Qwen32B）进一步提升准确率至 64.2%。
3. **定向再生**：假设引导的增量再生在所有配置中编辑距离最低（0.244），是非定向方法（Manual Reprompt 0.574, Full Regeneration 0.549, IPE 0.306）的 **1.3–2.4 倍**，但语法有效性只有 83.3%，不及 100% 的基线。级联编辑是主要失效原因。
4. **分类分布**：输入验证、数据格式、错误处理、性能假设普遍（>75% 任务），持久化和安全假设罕见但关键。离线基线在罕见类别上几乎为零。
5. **可解释性**：将假设显式化为结构化记录，使开发者可以审计、修改、追溯代码中的决策，提升了 LLM 代码生成的透明度和可控性。

### 7. 优点

- **首次定义并系统化“隐含假设”问题**，提出六分类法（T1–T6），并提供了结构化记录 schema。
- **增量再生**机制能够仅修改受假设影响的代码区域，实验证明编辑距离显著低于非定向方法，支持更精细的控制。
- **综合基准**包含人工验证的子集和严格的决策级匹配度量，避免了仅基于类别匹配的膨胀分数。
- **跨模型验证**：关键结论基于与注释模型无关的开源骨干（Qwen32B、DeepSeek），降低了自洽性风险。
- **公开全部代码、数据和评估脚本**（Zenodo DOI），实验可完全复现。
- **交互式界面**的设计使得开发者可以低门槛使用，提升了实用性。

### 8. 不足与局限

- **基准仅覆盖 Python**：结论能否推广到静态类型语言（Rust、Java）或工业级多文件仓库尚不确定。
- **扩展集（150 个任务）的假设注释由 GPT‑4o 产生，未人工验证**，导致 RQ1 和 RQ2 全量分析存在模型偏差风险。作者虽标记了 GPT‑4o 结果的自洽性标记，但对其他模型的评估仍以该基准为参考。
- **提取在决策级匹配下表现有限**（最好 F1=0.66），说明当前 LLM 仍然难以精确识别出了什么样的具体决策。
- **代码适应性评估未进行单元测试检验**，仅依赖语法有效性，可能高分低能（语法能通过但语义错误）。
- **增量再生的语法有效性仅 83.3%**，级联编辑问题未解决，限制了实际可用性。
- **缺乏用户研究**：未评估开发者实际使用 AssumptionMiner 时能否更准确地发现并修正假设，以及其带来的认知负荷。
- **仅评估单函数/单文件**，未考虑跨文件、跨模块的假设传递。
- **未涉及安全性和持久化假设在更大代码库中的表现**，这两个类别在基准中只有少量实例。
