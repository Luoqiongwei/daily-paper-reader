## 摘要
大型语言模型（LLM）智能体现在能够良好地处理面向正确性的仓库级任务，包括SWE-Bench问题解决和实际代码库中的功能实现。然而，它们在仓库级代码优化方面仍存在困难，这需要在保持行为的同时提升运行时性能。在此场景下，仅通过测试是不够的；补丁必须保持行为、实现代码优化，并接近专家的加速效果。当前的智能体常常错过隐藏在抽象层和原生扩展后的瓶颈，在浅层加速后停止，或者对代码补丁测试不足，从而可能悄然破坏边界情况。我们提出PerfAgent，一种基于Profiler引导、验证器在环的工作流程，为现成的编码智能体提供所需的反馈，以发现真正的热点，超越首个通过测试的补丁进行改进，并使用Profiler证据而非仅凭计时来决定下一步优化什么。在两个具有挑战性的优化基准测试GSO和SWE-fficiency-Lite上，PerfAgent使匹配专家的补丁率比使用GPT-5.1的OpenHands提升了一倍以上，在GSO上从19.6%提升至39.2%，在SWE-fficiency-Lite上从26%提升至74%。它还以显著更低的成本超越了最优五选一的基线，表明提升来源于更好的反馈，而非额外的测试时采样。

## Abstract
Large language model (LLM) agents now perform well on correctness-oriented repository-level tasks, including SWE-Bench issue resolution and feature implementation in real codebases. However, they still struggle with repository-level code optimization, which requires preserving behavior while improving runtime performance. Passing tests is not enough in this setting; a patch must preserve behavior, implement code optimization, and approach expert speedups. Current agents often miss bottlenecks hidden behind abstraction layers and native extensions, stop after shallow speedups, or insufficiently test the code patches that thus may silently break edge cases. We present PerfAgent, a profiler-guided, verifier-in-the-loop workflow that gives an off-the-shelf coding agent the feedback needed to find real hotspots, improve beyond the first passing patch, and use profiler evidence rather than timing alone to decide what to optimize next. On two challenging optimization benchmarks, GSO and SWE-fficiency-Lite, PerfAgent more than doubles the rate of expert-matching patches over OpenHands with GPT-5.1, improving from 19.6% to 39.2% on GSO and from 26% to 74% on SWE-fficiency-Lite. It also surpasses an oracle best-of-five baseline at substantially lower cost, showing that the gains come from better feedback rather than additional test-time sampling.

### 1. 论文的核心问题与整体含义（研究动机和背景）
- **问题**：现有大型语言模型（LLM）代理在面向正确性的仓库级任务（如SWE-Bench问题解决）上表现优异，但在仓库级代码优化（Repository-Level Code Optimization）上存在严重不足。代码优化不仅要求补丁保持功能正确性，还必须提升运行时性能，接近人类专家的加速效果。
- **关键挑战**：
    - 代理常遗漏隐藏在抽象层和原生扩展（C/C++/Rust）背后的真正瓶颈。
    - 代理在获得首个通过测试的补丁后过早停止，无法进一步深度优化。
    - 代理对补丁测试范围过于狭窄，导致优化后的代码在边缘用例上静默失效。
- **意义**：代码优化是比纯正确性更严格的要求，现有通用代理无法胜任，需要专门设计反馈机制。

### 2. 论文提出的方法论：核心思想、关键技术细节、算法流程
- **核心思想**：PerfAgent 是一个**Profiler引导、验证器在环（verifier-in-the-loop）**的工作流，通过三个专用组件解决上述三个失败模式：
    1. **Curated Profiler Summary（精选性能分析摘要）**：
        - 使用低开销采样分析器 **py-spy**（而非Python内置cProfile），能同时捕获Python层和原生扩展层的调用栈。
        - 对原始样本进行过滤（剔除初始化无关帧）、聚合为热点摘要，并通过一个LLM调用将其浓缩成自然语言描述，避免信息淹没。
        - 提供每个热点的位置、调用上下文、自时间/总时间、是否位于外部库的标记。
    2. **Objective-Driven Loop Controller（目标驱动循环控制器）**：
        - 架构：每次迭代包含“代理内阶段”（Agent Phase）和“外部评估阶段”（Evaluation Phase）。代理提交补丁后，控制器重建仓库、运行选择性测试、重新Profiling，将新的热点摘要和实测加速比反馈给代理进行下一轮优化。
        - 不满足于首个通过补丁：强制代理进行最多 θ 轮（实验中取5轮）迭代，保留所有轮次中加速比最高的正确补丁（而非最后一轮）。
    3. **Selective Validation（选择性验证）**：
        - 使用 **pytest-testmon** 插件，根据代码覆盖率信息仅选择受代理修改影响的测试用例进行验证，将测试量减少66%~99%（GSO）和47%~98%（SWE-fficiency-Lite）。
        - 返回测试失败作为反馈，防止优化过程中引入回归。
- **算法流程**（文字说明）：
    1. 初始：在未修改的基准仓库上运行py-spy，生成首轮热点摘要。
    2. 循环 for i = 1 to θ：
        - 代理收到当前热点摘要 + 上一轮（若有）的加速比和测试反馈。
        - 代理编辑代码并提交补丁。
        - 控制器应用补丁、重建仓库、运行pytest-testmon选择性测试。
        - 若测试失败，将错误输出返回给代理；否则运行py-spy更新热点摘要并测量工作负载上的加速比。
        - 将新摘要和加速比一并返回给代理。
    3. 结束：选择所有通过测试的补丁中加速比最高的作为最终输出。
- **实现基础**：基于 Mini-SWE-Agent，但宣称可应用于任何编码代理（如OpenHands, Trae Agent, iSWE-Agent）。

### 7. 优点
- **针对性强的设计**：三个机制精确对应三种失败模式，而非通用尝试。
- **使用低开销原生感知profiler**：py-spy可洞察native扩展，克服cProfile短板。

- **奖励黑客检测组合**：结合SWE-fficiency的堆栈内省检测和GSO的LLM-as-judge，增强鲁棒性。

- **详细案例分析**：通过numpy.char.replace例子生动展示逐轮迭代优化过程。

### 8. 不足与局限
- **实验覆盖范围有限**：基准仅含Python仓库（约12个不同仓库），未涉及Java、Go、Rust等语言；代理基于Python工具链，可能不直接迁移。
