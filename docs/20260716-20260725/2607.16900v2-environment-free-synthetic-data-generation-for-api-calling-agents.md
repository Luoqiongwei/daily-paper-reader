## 摘要
训练API调用的大语言模型（LLM）智能体需要大量高质量轨迹。然而，大规模收集此类数据通常需要完全实现的环境，包括可执行的API和预填充的真实后端数据库，这给可扩展性带来了主要瓶颈。为克服这一问题，我们提出了一种无环境的合成数据生成方法，利用LLM作为即时数字世界模型。仅给定API规范，我们的方法生成模拟智能体与有状态环境交互的轨迹。具体而言，LLM首先生成可使用所提供API解决的多样化任务；然后，教师智能体迭代解决每个任务，同时LLM模拟器根据任务上下文和模拟历史生成连贯的合成API响应；最后，LLM裁判过滤轨迹以确保最终数据集的质量。我们在具有挑战性的AppWorld和OfficeBench基准上评估了该方法，这些基准包含信息检索和状态更改任务。在我们的合成数据上微调模型带来了显著的性能提升，证明无需任何可执行环境即可为API调用智能体生成有效监督。我们的结果确立了基于LLM的API模拟作为跨多种API生态训练智能体的实用、可扩展解决方案。

## Abstract
Training API-calling large language model (LLM) agents demands massive amounts of high-quality trajectories. However, collecting such data at scale typically requires fully implemented environments with executable APIs and realistic, pre-populated backend databases, creating a major bottleneck for scalability. To overcome this, we propose an environment-free synthetic data generation approach that leverages LLMs as on-the-fly digital world models. Given only API specifications, our method generates trajectories mimicking interactions between an agent and a stateful environment. Specifically, an LLM first generates diverse tasks solvable with the provided APIs. A teacher agent then iteratively solves each task while an LLM simulator generates coherent synthetic API responses conditioned on the task context and simulation history. Finally, an LLM judge filters the trajectories to ensure the quality of the resulting dataset. We evaluate our approach on the challenging AppWorld and OfficeBench benchmarks, which include both information-retrieval and state-changing tasks. Fine-tuning models on our synthetic data yields significant performance gains, demonstrating that effective supervision for API-calling agents can be generated without any executable environment. Our results establish LLM-based API simulation as a practical, scalable solution for training agents across diverse API ecosystems.

## 2. 方法论
- **核心思想**：使用LLM作为即时数字世界模型，根据API规范、任务上下文和历史交互生成连续的、有状态的API响应，从而在纯模拟中完成多步轨迹，无需真实API执行。
- **关键技术细节**：
  - **ESAT管道**：由三个阶段组成：
    1. **任务合成（Task Synthesis）**：基于配置桶（难度、动作类型、任务焦点、应用数、API范围）生成多样化任务。采用逆频率采样确保应用/API覆盖均匀。LLM裁判过滤无效任务，LLM重写器将过程性描述压缩为意图级请求。
    2. **轨迹合成（Trajectory Synthesis）**：教师LLM智能体迭代调用API；LLM模拟器根据完整上下文（API规范、调用参数、任务、历史、用户信息、当前时间）生成响应。模拟器遵循四条规则：数据一致性、数据多样性、数据真实性、模式合规。并引入程序化输入验证、输出模式校验、语义一致性检查（针对读API）及重试机制。
    3. **轨迹过滤（Trajectory Filtering）**：LLM裁判评估轨迹的正确性、完整性和冗余性，多次评估后取多数票保留高质量轨迹。
- **算法流程**：输入API规范 → 桶化生成任务 → LLM裁判过滤 → 任务重写（LLM） → 最终裁判 → 教师智能体+LLM模拟器迭代交互生成轨迹 → LLM裁判过滤 → 输出高质量轨迹数据集。

## 3. 实验设计
- **数据集/场景**：
  - **AppWorld**：9个应用，457个API，平均任务需要10个API和45次调用。提供Test-Normal（168任务）和Test-Challenge（417任务，含两个保留不参与训练的应用）两个测试集。
  - **OfficeBench**：8个应用，20个API，任务涉及跨应用工作流。评估26个双应用和46个三应用任务。
- **基准与对比方法**：
  - 离线零样本（Gemini-3.1-Pro, GLM-5.1-FP8, GPT-4o, Nemotron-3-120B）。
  - 使用现有合成数据集微调：ToolAlpaca、ToolACE、Nemotron。
  - Simia（基于种子轨迹合成数据的方法）。
  - 真实环境数据AWT（在AppWorld真实环境中用教师智能体生成的轨迹）。
- **评估指标**：AppWorld中报告任务目标完成率（TGC）和场景目标完成率（SGC）；OfficeBench中报告通过率（pass rate）。所有结果均基于8次独立推理运行的平均值。
- **模型**：微调Qwen3（1.7B, 4B, 8B, 14B）和Qwen3.5（2B, 4B, 9B, 27B）共8个模型。
- **实验组**：
  - 使用ESAT-S52（52个合成应用，独立于AppWorld）、ESAT-AW7（7个AppWorld应用）、ESAT-S52-AW7（合并）、AWT、以及它们的组合。
  - 消融实验：不同LLM裁判（GLM-5.1-FP8 vs Gemini-3.1-Pro）、模拟器质量分析、与现有合成数据集对比、人类评估LLM裁判一致性。

## 4. 资源与算力
- **数据合成**：任务生成使用GLM-4.7-FP8；轨迹合成中教师智能体和API模拟器使用GLM-5.1-FP8；轨迹过滤使用Gemini-3.1-Pro。
- **训练**：小模型（<14B）使用8张H100 GPU，14B及以上使用8张B200 GPU。训练使用AdamW优化器，学习率2e-5，线性衰减，1%预热。默认训练10个epoch（Qwen3.5家族使用5个epoch以避免过拟合）。未报告每轮训练时长。
- **推理**：使用vLLM进行高效推理，温度设为1.0，每个任务采样8次。

## 5. 实验数量与充分性
- **实验数量**：涵盖8个模型在两个基准上的多个数据配置（零样本、ESAT-S52、ESAT-S52-AW7、AWT、组合等），共约30+组主要实验结果。此外还包含裁判质量、模拟器失败分析、与现有数据集对比等消融与诊断实验。

## 6. 主要结论与发现
- 训练在ESAT合成数据上的模型在所有模型规模上均获得显著性能提升（AppWorld上最高提升50.5%，OfficeBench上最高提升60.5%）。
- 在AppWorld上，使用ESAT-S52-AW7数据微调的性能普遍优于使用真实环境数据（AWT）微调的性能。
- 小模型（如Qwen3-4B、Qwen3.5-4B）通过ESAT数据微调后可以超越更大模型（如GPT-4o、Nemotron-3-120B）在零样本下的性能。
- ESAT数据对新API（合成应用）具有良好的泛化能力，证明技能可以跨域迁移。
- LLM裁判（Gemini-3.1-Pro）在轨迹过滤中有效提升数据质量，与人类标注者高度一致。
- 模拟器在短输出时失败率低（2-3%），但随输出长度增加失败率上升（>2k token时达23%），表明长文本一致性是当前瓶颈。

## 7. 优点
- **方法创新**：首次提出完全无环境的合成轨迹生成管道，将数据生成简化为轻量级规范问题，显著降低扩展新API的门槛。
- **状态一致性**：模拟器通过维护逐应用历史、规则约束和多重校验，实现了跨多步调用的状态连贯性，优于以往基于单步或会话一致性的模拟方法。
- **覆盖和多样性**：桶化生成、逆频率采样、任务重写等设计确保任务覆盖各难度、动作类型和API使用频率，避免数据分布集中。
- **实验严谨**：大量实验涵盖多种模型、数据集和对比基线，并进行了裁判质量、模拟器质量、人类评估等诊断，论证充分。
- **实用性强**：小模型通过ESAT数据可达到接近乃至超越商用大模型的性能，降低了实际部署成本。

## 8. 不足与局限
- **模拟器限制**：处理长输出响应时失败率较高（>2k token约23%），可能影响包含大量数据（如长列表、详细描述）的任务轨迹质量。模拟器依赖GLM-5.1-FP8，使用更强模型可能缓解。
- **多应用任务分布倾斜**：生成的任务和轨迹中，单应用任务占主导（ESAT-AW7中66%轨迹为单应用），二/三应用任务比例较低，可能削弱跨应用协作能力的训练。
- **依赖LLM裁判**：裁判的质量直接影响数据筛选效果，文中所示Gemini优于GLM，但裁判本身可能引入偏差或漏判。
- **评估范围有限**：仅在AppWorld和OfficeBench两个受限基准上验证，未在更多真实世界API集（如数百个真实服务）上测试，跨领域泛化性需更多证据。
- **未报告训练成本**：未提供数据生成和模型微调的完整计算时间、成本等，不利于资源评估。
- **安全与隐私风险**：合成数据可能包含虚构但敏感的信息（如信用卡号、用户身份），论文未讨论数据脱敏或伦理审查。
