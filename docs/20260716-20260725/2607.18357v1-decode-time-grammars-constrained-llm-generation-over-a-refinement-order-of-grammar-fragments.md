## 摘要
大型语言模型现在编写着全球越来越多的代码，尤其是在那些编译、执行或分发生成的代码而无需逐行审查的智能体和服务器系统中。这对于主流语言效果良好，但对于低资源编程环境（如领域特定语言、自定义库API和命令行工具）仍然脆弱。即使在文法约束解码下，模型仍可能生成在当前环境中无效的引用：从未声明的缓冲区、模式中不存在的列、库未提供的函数或不支持的CLI选项。本文介绍了解码时间文法：在生成过程中从运行时环境Gamma实例化的文法片段。区域特定的策略为每个孔选择片段，紧缩操作符将开放引用位置替换为Gamma类型的槽，其候选对象正是该点可用的名称、字段、API或选项。新生成的声明在解码后续区域之前进入Gamma，因此约束文法可以依赖于已生成的前缀。这不仅确保了语法正确性，还通过防止对未定义符号的引用来确保语义正确性。我们将文法片段形式化为按精化排序的环境索引文法，证明了Gamma槽化片段的No-Ghost可靠性，展示了精化保留此支持集保证，并刻画了掩码可强制执行属性的边界。我们在gproj中实现了该方法，包括离线文法归纳和在线策略解析。在TileLang、SQL和P4上，使用0.6B至236B参数的模型，gproj通过构造消除了幽灵引用，开销略高于标准约束解码。

## Abstract
Large language models now write a growing share of the world's code, increasingly inside agents and serving systems that compile, execute, or dispatch generated code without line-by-line review. This works well for mainstream languages but remains brittle for low-resource programming surfaces such as domain-specific languages, custom library APIs, and command-line tools. Even under grammar-constrained decoding, a model can still produce references invalid in the current environment: a buffer never declared, a column absent from the schema, a function the library does not provide, or an unsupported CLI option.   This paper introduces decode-time grammars: grammar fragments instantiated during generation from a runtime environment Gamma. A region-specific policy selects a fragment for each hole, and a tightening operator replaces open reference positions with Gamma-typed slots whose candidates are exactly the names, fields, APIs, or options available at that point. Newly generated declarations enter Gamma before later regions are decoded, so the constraining grammar can depend on the prefix already generated. This ensures not only grammatical correctness but also semantic correctness, by preventing references to undefined symbols.   We formalize grammar fragments as environment-indexed grammars ordered by refinement, prove No-Ghost soundness for Gamma-slotted fragments, show that refinement preserves this support-set guarantee, and characterize the boundary of mask-enforceable properties. We implement the approach in gproj with offline grammar induction and online policy resolution. Across TileLang, SQL, and P4, with models from 0.6B to 236B parameters, gproj eliminates ghost references by construction at moderate overhead over standard constrained decoding.

# 解码时间文法：基于文法片段精化顺序的约束式大语言模型生成

## 1. 核心问题与整体含义（研究动机和背景）
大型语言模型（LLM）在编写代码时，尤其在智能体和服务器场景中，生成的代码常直接提交给编译器、数据库或 shell 执行，缺乏逐行审查。主流语言表现良好，但**低资源编程表面**（领域特定语言 DSL、自定义库 API、命令行工具）仍然脆弱。即使采用标准语法约束解码（如 XGrammar），模型仍会产生**幽灵引用**——在语法上合法但在当前运行环境中无效的引用，例如：未声明的缓冲区、不存在的数据表列、库中不提供的 API 或命令行不支持的选项。这些错误源于负迁移（模型倾向于使用邻近的方言、错误版本的 API 等），且单纯提高模型能力无法消除，因为它们往往具有高概率。

现有方法（固定文法、提示工程、微调、重试）只能降低概率而不能从支持集（support set）中移除非法引用。**本文提出解码时间文法（Decode-Time Grammars）**：在生成过程中，根据运行时环境 Γ（包含作用域内可用的名称、字段、API、选项等）动态实例化文法片段，将开放引用位置替换为 Γ 类型槽，从而在 token 层面上保证生成的引用只在当前环境有效，实现语法和语义的正确性。

## 2. 方法论：核心思想、关键技术细节、公式或算法
### 核心思想
- 将运行环境 Γ 作为输入整合到解码循环中，生成过程中 **声明的展开会扩充 Γ**，后续引用区域受更新后的 Γ 约束。
- 一个 DSL 的同一个语义结构可以有多个文法片段，按**精化序（refinement order ⊑）** 组织，从最严格的 pin（完全锁定）到最宽松的 base（开放标识符）。其中紧致算子 τ_Γ 将开放引用位置转变为 Γ 类型槽，是实现无幽灵引用的关键边。

### 关键技术细节
1. **孔洞与策略**：生成程序被表示为带类型孔洞的模板。每遇到一个孔洞 (s, Γ)，区域策略 π(s, Γ) 选择一个文法片段。
2. **Γ 类型槽与实例化**：槽携带查询 `query_slot : Γ → P_fin(Names)`，例如 `Γ.names(sort=Buffer, shape=σ)`。实例化时，槽被替换为候选的转义交替（escaped alternation），编译进 token 掩码。
3. **动态环境**：Γ = 持久全局层 + 栈式区域局部帧，声明写入当前帧，帧入栈/出栈对应作用域进入/离开。
4. **构造级保证**：
   - **No-Ghost 可靠性定理**：若片段中参考位置均为 Γ 槽且查询结果非空、结果 ⊆ dom(Γ)，则所有生成的引用都在 dom(Γ) 内（证明基于转义引理）。
   - **精化保持支持集可靠性**：更紧的片段保持更松片段的无幽灵保证，可在运行时安全降级（fallback）。
   - **必要性定理 (Prop. 3)**：不存在有限预编译文法族能在所有前缀下同时满足无幽灵和非阻塞；对每个前缀，最大可靠支持集必须动态合成为 dom(Γ(p))。

5. **离线诱导（TemplateInductor）**：从少量语料（K 个同族程序）出发，使用反合一（anti-unification）提取骨架，由 LLM 建议文法片段，再通过**硬门（hard gate）** 验证：语料正例必须被接受、自动生成的鬼魂负例必须被拒绝（采用与运行时代码相同的引擎语义）。诱导产生四阶精化阶梯：base → gamma（Γ 类型槽） → ctx（属性过滤） → pin（黄金模板）。

### 伪算法流程（文字说明）
1. 用户输入任务 → Stage 1 (Sketch search): LLM 生成程序骨架，标记类型孔洞。
2. Stage 2 (Constrained realization): gproj 执行器按孔洞遍历；对每个孔洞：
   - 查询当前 Γ，策略 π 选择片段；
   - 应用 τ_Γ：将片段中开放引用位置替换为 Γ 类型槽（查询结果集合的转义交替）；
   - 提交给掩码引擎（XGrammar）编译为 token 自动机；
   - LLM 解码受限区域，每一步掩码只允许支持集中的 token；
   - 区域完成后，从输出中提取声明，更新 Γ。
3. 完成后返回完整程序。若某槽查询结果为空，则沿精化序降级使用更松片段（如开放标识符）以维持生成，同时标记诊断信息。

## 8. 不足与局限
- **保证边界有限**：No-Ghost 保证仅针对 Γ 可列举的属性（名称、类型、形状等），不覆盖语义正确性、终止性、数值精度、可变属性的不变性等。超出 Γ 范围的性质需要外部验证器或降级回宽松片段。
- **依赖于环境保真度**：若声明提取或帧管理出现错误（trusted interface 故障），则保证可能失效。引擎与形式语义的一致性通过差分测试验证，但未覆盖所有极端情况。
- **诱导质量依赖强 LLM**：TemplateInductor 使用强 LLM 提议片段，质量不稳定时可能需人工修正。目前未提供自动修复或验证之外的反馈回路。
- **部分场景不适用**：通用语言（C++、Python）需要堆、别名、同步等更丰富的分析，超出单调 Γ 模型能力；正则表达式等无运行时环境的场景无法应用。
