## 摘要
大型语言模型（LLM）使自动程序修复（APR）对现实世界中的错误越来越实用，但直接从错误报告进行修复仍然约束不足。错误复现测试（BRT）通过将错误报告转化为可执行的、针对特定错误的信号来弥补这一差距，该信号可以指导修复并验证候选补丁。因此，现有研究已将BRT生成作为APR中的核心子问题，并主要使用失败到通过（F->P）标准来评估生成的BRT，该标准要求测试在错误代码上失败，但在正确修复上通过。我们表明，当BRT的目标是改进下游修复时，仅靠F->P是不够的。具体来说，一些F->P BRT是宽松的：它们复现了观察到的症状，但仍然允许看似合理但错误的补丁。我们通过将F->P BRT分为严格和宽松两类来形式化这一缺失的质量维度，并实证表明只有前者能持续提高修复成功率。我们进一步发现，协同生成引入了测试-修复错误耦合，即当生成的补丁和生成的测试都错误时，轨迹内的失败到通过（F->P）检查仍可能通过。基于这些发现，我们提出CoHarden，一种协同生成框架，使用Lax信号作为循环内收敛标准。CoHarden首先生成一个测试，然后再进行修复，然后迭代地强化测试和修复，以对抗存活的变异补丁，直到生成的测试不再允许Lax回归。实验表明，CoHarden在SWE-bench Verified上达到了69.4%的解决率和78.9%的F->P率，在解决率方面分别比最强的仅修复基线和协同生成基线高出9.6和7.9个百分点，并且在不同的LLM骨干和基准测试中表现一致。

## Abstract
Large language models (LLMs) have made automated program repair (APR) increasingly practical for real-world bugs, but repairing directly from bug reports remains underconstrained. Bug reproduction tests (BRTs) help close this gap by turning a bug report into an executable, bug-specific signal that can guide repair and validate candidate patches. Existing work has therefore studied BRT generation as a core subproblem in APR and mainly evaluates a generated BRT using the fail-to-pass (F->P) criterion, which requires the test to fail on the buggy code but pass on the golden fix. We show that F->P alone is insufficient when the goal of a BRT is to improve downstream repair. In particular, some F->P BRTs are lax, reproducing the observed symptom yet still admitting plausible-but-incorrect patches. We formalize this missing quality dimension by separating F->P BRTs into rigorous and lax ones, and show empirically that only the former consistently improve repair success. We further find that co-generation introduces test--fix error coupling, where the in-trajectory fail-to-pass (F->P) check can pass even when both the generated patch and generated test are wrong. Based on these findings, we propose CoHarden, a co-generation framework that uses the Lax signal as an in-loop convergence criterion. CoHarden first generates a test before any fix, then iteratively hardens the test and fix against surviving mutation patches until the generated test no longer admits Lax regressions. Experiments show that CoHarden reaches 69.4% Resolved and 78.9% F->P on SWE-bench Verified, outperforming the strongest fix-only and cogeneration baselines by +9.6 and +7.9 percentage points in Resolved, respectively, with consistent gains across LLM backbones and benchmarks.

## 1. 核心问题与整体含义（研究动机和背景）

- **研究背景**：大型语言模型（LLM）驱动的自动程序修复（APR）技术已能生成看似合理的补丁，但正确性难以保证。直接根据自然语言错误报告进行修复存在约束不足的问题，因为报告往往不完整，许多候选补丁表面合理但实际错误。
- **现有方法**：Bug Reproduction Tests（BRTs）被用来弥补这一差距，将错误报告转化为可执行的、针对特定错误的信号，辅助修复验证。已有工作将BRT生成作为APR核心子问题，并使用**Fail-to-Pass（F→P）**标准评价BRT质量：测试必须在错误代码上失败，在正确修复上通过。
- **核心问题**：论文发现仅靠F→P标准是不够的。许多满足F→P的BRT是“宽松的”（Lax），它们能复现观察到的症状，但仍然接受看似合理但错误的补丁。因此，需要更精细的质量维度来区分“严格”（Rigorous）和“宽松”（Lax）的BRT，并解决协同生成（co-generation）中测试与修复错误耦合的问题。
- **整体含义**：提出了一个名为CoHarden的协同生成框架，通过在迭代循环中强化测试和修复，使测试不再允许宽松回归（Lax regressions），从而显著提高修复成功率。

## 2. 方法论：核心思想、关键技术细节、算法流程

- **核心思想**：将BRT的质量从二元的F→P扩展到三分类：Rigorous（严格）、Lax（宽松）、Misaligned（错位）。仅Rigorous测试能有效约束修复空间。基于此，设计两阶段循环：第一阶段先生成测试（lax-init），第二阶段迭代硬化（hardening）测试与修复，直到测试不再被变异补丁宽松通过。
- **关键技术细节**：
  - **Mutation Patch Evaluation (MPE)**：通过构建变异补丁池（由LLM基于5种语义算子生成：vanilla、symptom suppression、incomplete fix、input-specific shortcut、behavior substitution），计算生成测试和黄金测试对每个变异补丁的通过/失败结果，形成2×2混淆矩阵，从而计算Laxity率（β/total），据此分类。
  - **Temporal Matrix**：在硬化循环中，由于无法使用黄金测试，改用上一轮测试作为参考，评估当前测试是否比上一轮更严格。矩阵的β细胞（当前测试通过但上一轮测试失败的变异补丁）计数表示Lax regressions。
  - **两阶段流程**：
    - **Phase 1 (Lax-init)**：仅生成一个重现测试t0，不进行任何源码修改，避免早期错位测试和测试-修复耦合。
    - **Phase 2 (Hardening)**：从t0引导出初始对(t1, c1)，然后每轮迭代：①从当前修复ck生成变异池Ck；②用tk和tk-1填充Temporal Matrix；③若Laxity率ℓk > τ（默认0.2），则测试回退到t0，保留修复，继续下一轮；若ℓk ≤ τ且测试有非平凡变化，则收敛；否则更新参考测试继续。
- **算法流程**（文字说明）：
  1. 输入：问题I，最大轮数K，变异算子O，每算子采样数N，容忍度τ。
  2. Phase 1: 调用Agent生成t0。
  3. Phase 2: 对k=1到K：
     - Agent联合生成(tk, ck)，给定当前参考测试和反馈。
     - 生成变异池Ck（每算子N个样本）。
     - 计算Temporal Matrix和Laxity率ℓk。
     - 若ℓk > τ，回退tk到t0，继续循环。
     - 否则若tk ≠ tref，返回(tk, ck)（收敛）。
     - 否则更新tref = tk，继续下一轮。
  4. 返回最后轮结果。

## 6. 主要结论与发现

- **F→P作为粗粒度过滤器有用，但不够精细**：F→P测试的修复增益完全集中在Rigorous测试中（Δ=+8.5 Resolved），而Lax测试提供零增益（Δ=0.0）。Misaligned测试甚至有害（Δ=-3.6）。
- **协同生成中测试与修复错误耦合**：cogeneration的联合失败率是独立预测的1.87倍；Lax测试出现在cogeneration自身输出中，导致早期停止而错误未修复。
- **CoHarden显著提高修复正确性**：在SWE-bench Verified上达到69.4% Resolved（比最强fix-only基线+9.6pp，比最强cogeneration基线+7.9pp），F→P达到78.9%。
- **跨骨干和跨基准一致增益**：GPT-5.4和Claude Opus 4.5上CoHarden均优于最强基线；SWE-bench Lite上Resolved 57.6%也领先。
- **两阶段均必要**：lax-init移除导致Resolved下降7.0pp；移除hardening导致下降8.4pp（且F→P高但效果差，表明Lax特征）。

## 7. 优点

- **揭示了F→P的不足**：提出了更精细的BRT质量维度（Rigorous/Lax/Misaligned），填补了现有评估空白。
- **创新方法**：将变异测试思想引入BRT评估，并设计了无需黄金参考的Temporal Matrix进行迭代硬化。
- **实证充分**：通过BRT注入和cogeneration两个场景的系统研究，验证了研究假设，方法设计有据可依。
- **泛化性好**：在多个LLM骨干和基准上一致改善，且成本与现有cogeneration方法相当。
- **可复用性**：PLUGGABLE CRITIC机制支持技能打包和动态反馈，易于扩展。

## 8. 不足与局限

- **变异池覆盖依赖LLM**：MPE和Temporal Matrix依赖LLM合成变异补丁，可能遗漏罕见或领域特定的Lax模式。
- **实验范围有限**：仅在Python基准（SWE-bench、SWT-bench）和OpenHands-style agent循环上评估，对其他语言、安全补丁、非agent系统未测试。
- **硬化循环饱和**：Resolved在R3后趋于平稳，可能由于测试与修复在循环中仍存在耦合，某些联合错误对Temporal Matrix不可见。
