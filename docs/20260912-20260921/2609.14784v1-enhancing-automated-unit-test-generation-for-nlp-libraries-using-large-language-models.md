## 摘要
像EvoSuite这样的自动化单元测试生成工具在通用软件上表现良好，但在处理自然语言处理（NLP）库等特定领域软件时往往力不从心，因为这类软件的输入必须遵循语义、句法和结构约束。大型语言模型（LLM）能够生成与领域相关的测试代码，但仅由LLM生成的测试往往无法编译或达到足够的覆盖率。我们提出LLMSuite，一种混合测试生成框架，它将自细化提示与类级LLM推理集成到基于搜索的测试过程中。在该机制中，LLM根据先前生成结果的反馈迭代改进其测试片段。这使模型能够生成越来越精确、与领域一致的代码片段，引导进化搜索去执行复杂且原本难以触及的行为。当底层进化算法在连续多代中没有目标得到改进时，这些细化后的片段会被解析并注入EvoSuite的种群，以扩展搜索空间。为支持评估，我们构建了一个新数据集，包含从五个广泛使用的Java NLP项目中抽取的100个类。我们还用Java重新实现了近期的混合SBST-LLM技术CodaMOSA，以便进行直接比较。在该数据集上，LLMSuite将分支覆盖率和行覆盖率分别提高约10%和8%，并且比CodaMOSA-J获得高11%的变异得分。与EvoSuite相比，LLMSuite的分支覆盖率和行覆盖率约高15%，变异得分高5%。相对于仅使用LLM的基线，它将结构覆盖率提高了36%，变异得分提高了约24.7个百分点。最后，LLMSuite通过执行通常未被测试的领域特定行为，补充了手工编写的测试套件。

## Abstract
Automated unit test generation tools like EvoSuite perform well on general-purpose software but often struggle with domain-specific software such as Natural Language Processing (NLP) libraries, where inputs must follow semantic, syntactic, and structural constraints. Large Language Models (LLMs) can generate domain-relevant test code, but tests produced by LLMs alone often fail to compile or achieve sufficient coverage. We propose LLMSuite, a hybrid test generation framework that integrates self-refinement prompting with class-level LLM reasoning into the search-based testing process. In this mechanism, the LLM iteratively improves its test snippets based on feedback from previous generations. This enables the model to produce increasingly precise, domain-consistent code fragments that steer the evolutionary search toward exercising complex and otherwise hard-to-reach behaviors. When no objective improves over multiple generations in the underlying evolutionary algorithm, these refined snippets are parsed and injected into EvoSuite's population to expand the search space. To support our evaluation, we constructed a new dataset comprising 100 classes drawn from five widely used Java NLP projects. We also re-implemented CodaMOSA, a recent hybrid SBST-LLM technique, in Java to enable a direct comparison. Across this dataset, LLMSuite improves branch and line coverage by approximately 10% and 8%, respectively, and achieves an 11% higher mutation score than CodaMOSA-J. Compared to EvoSuite, LLMSuite yields roughly 15% higher branch and line coverage and 5% higher mutation score. Against an LLM-only baseline, it improves structural coverage by 36% and mutation score by about 24.7 percentage points. Finally, LLMSuite complements manually written test suites by exercising domain-specific behaviors that are often left untested.

## 1. 核心问题与研究动机

- **背景**：自动化单元测试生成工具（如 EvoSuite、Randoop）在通用软件上表现良好，但在**领域特定软件**（尤其是 NLP 库）上效果显著下降。
- **根本困难**：NLP 库的测试输入必须满足**语义（领域知识）、句法（语法正确句子、合法解析树）和结构（输入数据格式、注解流水线）**三重约束，传统基于搜索的测试（SBST）难以自行构造这类输入。
- **典型例证**：论文以 Stanford CoreNLP 的 `MorphaAnnotator` 为例——处理 `gave_up` 这类短语动词需要特定标注与下划线格式，EvoSuite 因（1）难以构造所需对象、（2）不了解领域输入格式、（3）无法组合多个相关输入属性而完全失败。
- **LLM 的局限**：LLM 能生成领域相关测试代码，但单独使用时常**无法编译**或**覆盖率不足**；而 SBST 擅长系统化路径探索但缺乏语义理解。
- **研究定位**：提出互补的**混合方法**，在 NLP 库这一尚未被系统探索的领域中，首次系统评估 SBST+LLM 混合测试生成。研究由 4 个 RQ 引导（对比效果、组件消融、功能类别差异、与人工测试的互补性）。

## 2. 方法论：LLMSuite 框架

### 核心思想
将 LLM 作为「领域语义注入器」嵌入 EvoSuite 的进化搜索循环：LLM 提供上下文洞察与语义有意义的输入，SBST 保证系统化探索。关键触发机制是**搜索停滞**。

### 关键技术细节

- **停滞检测与触发**：当 DynaMOSA 的任一目标连续 **S = 20 代**无改进时，判定为停滞点，调用 LLM 生成新测试片段；最多可触发 **L = 5 次**。
- **三阶段 LLM 提示流程**：
  1. **初始测试生成**（不强制 EvoSuite 格式，以保留创造力）；
  2. **格式重构**（将 helper 方法内联，转换为 EvoSuite 自包含格式）；
  3. **自精炼（Self-Refine）**：迭代 **T = 5 轮**，每轮让 LLM 分析未覆盖场景、列出未测用例、生成边界/角落/失败点测试；保留对话历史作为反馈，生成结果按测试名去重放入共享池。
- **提示工程**：遵循开发者人格设定、精确可执行指令、Chain-of-Thought 推理、标准化输入/输出格式（`[TEST]...[/TEST]`、`[CODE]...[/CODE]`）四项最佳实践；将 Madaan 等人的「反馈+精炼」双提示**统一为单提示**以减少调用次数。
- **上下文层级**：默认采用**类级提示**（而非 CodaMOSA 的方法级），提供更丰富上下文并减少提示数量。
- **解析与注入**：自研 `LLM2EvoSuiteParser`（基于 Spoon 静态分析）将 LLM 文本代码转为 EvoSuite 内部表示，支持嵌套调用、varargs、多维数组、赋值、mock 语句；对不支持构造（循环、lambda、try-catch）选择性抽取合法子组件，并做宽松参数匹配以跳过幻觉行。
- **幻觉过滤**：先启发式修复（缺逗号/括号、语法校验 ANTLR），无法修复则注释掉幻觉行及其依赖行，保留其余合法语句。
- **搜索集成**：解析后的合法测试与当前种群**并集合并**，EvoSuite 重新排序更新适应度，LLM 生成测试可参与交叉与变异，从而演化出单独搜索无法达到的输入（如 `give_up` 与 `NN` 标签交叉触发异常）。
- **最终验证**：搜索结束后编译所有测试，确保仅因断言失败而非其他问题（如幻觉代码）失败。

## 3. 实验设计

### 数据集 / Benchmark
- 自建新数据集：从 **5 个广泛使用的 Java NLP 库**中抽取 **100 个类**（CoreNLP 42、OpenNLP 17、Mallet 16、GATE 11、CogCompNLP 14），兼容 Java 8/11/17。
- 采集流程：过滤静态/抽象/私有类 → 按 WMC、分支数、非静态方法数归一化打分排序取每项目前 50 → 人工审阅 JavaDoc 归类 → 选出 100 个代表性类。
- 划分为 **9 个功能类别**（Coreference、Data Structures、Information Extraction、Linguistic Labeling、ML Algorithms、Normalization、Parser、Segmentation、Topic Modeling）。
- RQ2 随机选取其中 **60 个类**以减少运行量；RQ4 仅 **27 个类**存在人工测试。

### 对比方法
- **EvoSuite**（DynaMOSA 策略）
- **LLMOnly**（仅 ChatGPT-4o-latest-2025-07-12 生成，不经解析器）
- **CodaMosa-J**（作者用 Java 重新实现的 CodaMOSA：MOSA 策略、方法级提示、低覆盖目标导向、walkthrough 流程）

### 度量指标
- 结构覆盖：指令/行覆盖、分支覆盖
- 变异得分：JUGE（内部用 PITest），并扩展 JUGE 支持 Java 11/17

### 统计方法
- 重复测量设计，每类每工具运行 **5 次**；温度固定为默认 1.00
- 类级：Wilcoxon 符号秩检验（α=0.05）
- 全局：Friedman 检验 + Conover 事后检验
- 效应量：Vargha–Delaney A₁₂（小/中/大：0.56/0.64/0.71）
- 95% 偏差校正 Bootstrap 置信区间，逐类判定胜/负/平

## 4. 资源与算力

- **硬件**：64 核 AMD EPYC 处理器 + 256 GB RAM 服务器；使用 Docker 并行化，每容器分配 6 CPU 核 + 16 GB RAM。
- **GPU**：使用 **1 块 NVIDIA L40S GPU** 运行开源模型 `code-llama:13b-instruct`（通过 Ollama 访问）。
- **时间预算**：每目标类 **900 秒（15 分钟）**，相比 EvoSuite 默认 60 秒大幅增加。
- **LLM 时间开销**：自精炼平均消耗 **148.2 秒**（零样本模式仅 16.1 秒）；作者指出该开销可与 SBST 并行执行以规避。
- **Token 与成本**：完整自精炼在 65 个公共类上消耗 **7,547,600 tokens / 455 次调用**，其中自精炼轮次占 **80.6%**；零样本为 688,549 tokens / 65 次调用。按 $5/百万输入、$15/百万输出估算，总成本约 **$46.62 vs $4.78**，即每类约 **$0.72 vs $0.07**。Round 1→5 的 token 从 952K 增至 1,485K（因保留对话历史）。
- **未进行任何模型训练**（纯推理使用）。

## 5. 实验数量与充分性

- **总运行量：3300 次** = (100 类 × 3 工具 + 60 类 × 6 变体) × 5 次重复。
- **RQ1**：4 个工具在 100 类上对比（分支/行覆盖、变异得分）+ 逐类胜率分析。
- **RQ2（消融）**：6 个变体，各只改动一个组件——(1) 静态字符串池替换、(2) 仅 1 次 LLM 调用（1x）、(3) 换成 CodeLLaMA 13B、(4) 零样本提示、(5) MOSA 替代 DynaMOSA、(6) 方法级提示。
- **RQ3**：按 9 个功能类别做覆盖对比 + 人工定性分析（哪些代码被谁覆盖）。
- **RQ4**：27 个类的人工测试 vs LLMSuite vs 组合，并对未覆盖代码块做 6 类缺口分类（VB/IVB/EX/AUX/MEO/PRB）。
- **补充分析**：幻觉分类（8,449 行分 5 类）、幻觉率与覆盖率提升的 Pearson 相关（−0.273）、训练数据污染检测（JPlag：平均相似度 4.48%，最大 12.05%）、解析管线流量分析（474,626 条语句 → 91.57% 可用 → 89.44% 转换成功）。
- **充分性评估**：实验设计较充分——多工具对比、系统消融、定性+定量结合、多次重复、采用领域标准统计流程（Arcuri & Briand 指南）与效应量+置信区间，公平性较好。
- **潜在公平性问题**：CodaMosa-J 为作者自行重实现（原版为 Python + Codex，现改用 ChatGPT-4o + 自研 Java 解析器），可能与原框架存在偏差；LLMOnly 不经解析器，理论上可能因解析器局限而受益/受损；仅 27 类有人工测试，RQ4 样本偏小。

## 6. 主要结论与发现

- **RQ1（有效性）**：LLMSuite 在所有指标上均优于三个基线。
  - 中位数分支覆盖 **68.60%** vs CodaMosa-J 58.03%、EvoSuite 53.33%、LLMOnly 32.64%
  - 中位数行覆盖 **73.49%** vs 65.62%、57.66%、35.94%
  - 中位数变异得分 **63.0%** vs 52.0%、58.0%、38.26%
  - 相对 CodaMosa-J：分支 **+10.57%**、行 **+7.87%**、变异 **+11%**；相对 EvoSuite：分支 **+15.27%**、行 **+15.94%**、变异 **+5%**；相对 LLMOnly：结构覆盖 **+36%**、变异 **+24.7 个百分点**
  - 统计显著（p≪0.05），A₁₂ 效应量大（vs CodaMosa-J 0.73、vs EvoSuite 0.72、vs LLMOnly 0.85），逐类胜率明显（如 vs EvoSuite 36 胜 2 负）。
  - **变异得分增益明显弱于结构覆盖**，作者归因于 LLMSuite 依赖 EvoSuite 生成断言，未能利用 LLM 更语义化的断言。
- **RQ2（组件贡献）**：默认配置显著优于全部 6 个变体。类级提示 > 方法级；自精炼 > 零样本（+4.82%）；5 次调用 > 1 次（+5.37%）；仅改进字符串输入反而下降 1.4%；CodeLLaMA 13B 因响应慢、上下文受限而下降 8.66%；DynaMOSA > MOSA。
- **RQ3（功能类别）**：LLMSuite 在几乎所有类别领先，仅在 ML Algorithms 微降 0.1%。增益最大为 Information Extraction（18%）、Coreference（8%）、Segmentation（7%）、Normalization（5%）、Linguistic Labeling（3%）。LLM 帮助的三个机制：(A) 构造对象与正确调用序列、(B) 生成领域特定文本输入（如 Treebank 格式）、(C) 推断配置/属性设置（如 `ssplit.htmlBoundariesToDiscard`）。**在数值计算/算法逻辑为主的类（如 KMeans）中收益有限**。
- **RQ4（与人工测试互补）**：人工测试平均分支覆盖 33.99%，LLMSuite 68.49%，**组合达 74.55%**（相对人工 +40.55%）；变异得分 38.1% → 58.06% → **63.54%**（+25.44%）。人工测试未覆盖块 530 个（VB，49%），LLMSuite 降至 222；MEO 从 121 降至 7；PRB 从 48 降至 10。

## 7. 优点

- **方法设计亮点**：
  - 将 LLM 定位为「停滞时的语义注入器」而非全流程替代，充分利用两种范式的互补性。
  - **类级提示 + 自精炼**的组合在消融中被证明是关键增益来源，且自精炼由「分析未覆盖场景→列清单→生成边界用例」的单提示统一实现，降低调用成本。
  - 自研解析器支持嵌套调用、varargs、多维数组、宽松参数匹配与幻觉行过滤，**91.57% 生成语句可用、89.44% 成功转换**，工程完成度高。
- **实验设计亮点**：
  - 构建了**首个面向 Java NLP 库的 100 类基准**，按功能类别平衡采样，并公开复现包。
  - 采用完整的非参数统计流程（Wilcoxon / Friedman / Conover / A₁₂ / Bootstrap CI）+ 逐类胜率，符合 SE 随机算法评估规范。
  - 补充了**成本-效益分析（token/美元）、幻觉分类、训练数据污染检测（JPlag）**，透明度高。
  - 定量之外辅以定性分析（RQ3/RQ4 人工分析未覆盖代码块并建立缺口分类），解释了"为什么有效"。

- **内部效度**：LLM 采样温度固定为 1.00，输出随机性仍会带来方差，论文以 5 次重复缓解，但未报告重复间方差或稳定性分析；自研解析器的宽松匹配策略也可能在"跳过幻觉行"的同时误删合法语句，其影响未被单独量化。
- **超参数敏感性未系统探索**：停滞阈值 S=20、最大触发次数 L=5、自精炼轮数 T=5 均采用固定设定，论文只对"1 次 vs 5 次调用"做了消融，未给出 S/L/T 的敏感性曲线或最优配置的实证依据，仅以成本-效益角度建议"按需调整 T"。
- **可复现性风险**：主实验依赖闭源模型快照 `ChatGPT-4o-latest-2025-07-12`，该快照可能随服务下线而不可复现；开源替代仅在消融中作为 CodeLLaMA 13B 出现，且表现下降 8.66%，说明方法对底层模型能力较为敏感。
- **基线覆盖有限**：对比对象为 EvoSuite、LLMOnly 与自实现 CodaMosa-J，未与近年其他 LLM 测试生成工作（如 ChatTester、TestPilot、Achilles 等）或 LLM+SBST 的其他混合范式直接比较，难以判断"停滞触发 + 类级提示 + 自精炼"这一组合在同类方法中的相对位置。
- **领域泛化的论证不足**：论文主张方法可推广到其他领域特定软件，但未提供任何跨领域（如数据库、编译器、科学计算库）的验证性实验，该论断仍属推测。

## 9. 总体评价与启示

- **核心贡献**：论文把"LLM 增强 SBST"这一思路从通用软件推进到**领域特定软件**这一更难、也更有价值的场景，并给出可运行的完整工程实现（LLMSuite）、首个 Java NLP 库 100 类基准、以及覆盖 4 个 RQ、3300 次运行的系统实证。
- **方法论启示**：最值得借鉴的不是"用 LLM 生成测试"本身，而是三点设计决策——(1) **以搜索停滞为信号**决定何时求助 LLM，把 LLM 调用从"全流程开销"变为"按需注入"；(2) **类级上下文 + 单提示自精炼**，在上下文丰富度与调用成本之间取得平衡；(3) **文本代码 → 内部表示的解析与幻觉过滤层**，这是让 LLM 输出真正进入进化循环的必要工程前提。
- **实践启示**：在 NLP/文本处理类库上，LLMSuite 相对 EvoSuite 的分支覆盖提升约 15 个百分点、相对 CodaMosa-J 约 10.6 个百分点，且与人工测试组合可达 74.55% 分支覆盖，说明**混合方案 + 人工测试**是当前最现实的落地组合，而非用 LLM 取代既有测试。
- **局限的启示**：变异得分增益明显弱于结构覆盖，暴露出"LLM 能生成更好的输入、却仍由 EvoSuite 写断言"这一瓶颈——**用 LLM 生成语义化断言/预期输出**是本文最直接、也最值得跟进的研究方向。同时，数值计算/算法逻辑类收益有限，提示未来工作应明确划定方法的适用边界，而非追求"通用优于一切基线"。
- **总体判断**：这是一篇工程完成度高、实验规范、透明度好（公开成本、幻觉率、污染检测）的系统性实证论文；其结论在给定基准与模型快照下可信，主要不确定性来自闭源模型依赖、自实现基线，以及覆盖率/变异得分作为测试质量代理指标的固有局限。
